## 4. 出包过程踩的三个坑（建议登记为 F23，附回滚方式）

### 坑 1 · `unity_builtin_extra` 写入时崩，两次，与磁盘/杀软无关

```
Failed to write file: Library/PlayerDataCache/Win64/Data/Resources/unity_builtin_extra
Assertion failed on expression: 'm_LockCount == 0'
Error building Player: 3 errors
```

第一次 21.3 秒、第二次 4.8 秒，同一文件同一行。已排除：磁盘（E: 空闲 154 GB、实测写入 2.4 GB/s）、杀软（电脑管家已退出）、缓存脏（删掉 528 MB `PlayerDataCache` 后重建照崩）。

**真因**：登记清单里含 `Hidden/Internal-Colored`，它被序列化成 `{fileID: 69, guid: ...e000...}` —— `e000` 系列是 **`Library/unity default resources`**，一个 `HideFlags.DontSave` 的引擎内部资产（Console 那条 `An asset is marked with HideFlags.DontSave but is included in the build` 警告点名的就是它），不是 `f000` 系列的 `unity_builtin_extra` 正规资源包。把内部资产塞进构建后，Unity 写 builtin_extra 时锁计数不归零 → 断言崩溃。

**修法**：不登记 `Hidden/Internal-Colored`（引擎自带，项目不该管），并在脚本里加**黑名单主动剔除**（`ForbiddenShaders`），因为运行中的编辑器内存里可能仍是含问题项的旧状态，而 `ProjectSettings` 不是普通资产、`AssetDatabase.Refresh()` 刷不动它。

**回滚方式**：把 `ForbiddenShaders` 清空即可；`Hidden/Internal-Colored` 被登记是崩溃的直接触发条件。

### 坑 2 · 着色器登记必须"出包前跑"，不能靠人手点 GUI

`BuildWindows()` 内部第一步就调 `ApplyAlwaysIncluded()`。顺序反了（先出包后登记）等于白打一次包 —— 首包 21:52 就是这么翻的车。

### 坑 3 · 出包路径不能取 `Directory.GetCurrentDirectory()`

Unity 从 Hub 启动、命令行启动、快捷方式启动，cwd 都可能不同。已改为 `Application.dataPath` 的父目录（恒为工程根）。取错不会报错，只会「包建到别处」。
