### 2.1 三栏与两条带

## 三、文案组（三项裁决，可独立判定）

### 3.1 编号（规格 §6.1）

| 位置 | 格式 | 实现 |
|---|---|---|
| 列表（设备管理 / 告警中心 / 动态行） | `2F-201` | `TwinCode.Short` |
| 异常 Top3 | `2F-201 空调` | `TwinCode.WithType` |
| 详情（窄态浮卡 / 全屏右栏） | `1号教学楼-2F-201-空调-001` | `TwinCode.Full` |

**房间号推导**：不另建表，由 `TwinSiteLayout.Rooms` 的 `Floor` + 同层序号推导
（`Floor + "F-" + Floor + NN`）：1F 第 1 个 → `1F-101`，2F 第 5 个 → `2F-205`。
新增房间只要进 `TwinSiteLayout` 就自动有编号。

**grep 验收**：
```
UI 层「把 TwinId 直接塞进 text」→ 0 处（收敛前 5 处）
TwinCode 调用点 → 25 处
```

### 3.2 状态词与健康条

- 状态词统一走 `TwinStatusPalette.Label`：正常 / 警告 / 告警 / 离线
- 新增 `HealthColor(normal, warning, alarm, offline)`，优先级 **离线 > Alarm > Warning > Normal**

**一个需要确认的口径**：健康条**本身仍是三段**（正常绿 / 告警红 / 离线灰，各段本色 ——
这是信息表达，改了就看不出"各占多少"），`HealthColor` 用在**百分比文字**上。
图纸画的是绿+橙分段，裁决文字是"按最严重级别取色" —— 两者只有这个解释能同时成立。

### 3.3 量词

- 设备计数统一 `TwinCode.UnitDevice = "台"`
- 「个监测点位」只在 L1 副标出现一次（`1号教学楼 · 已接入 53 个点位 · 室内 + 室外路灯`）

## 五、没做 / 已知风险

**没做**：
- 全屏 L2 的**电力管理 / 告警中心 / 数据统计**三页只给空状态（P29-5 范围，规格 §10 明确不做）
- 详情卡在全屏的「开关按钮」未做（只读 4 项指标）—— 涉及 `TwinCommandCenter` 下发链路，风险高于本轮范围
- 截图（纪律要求交主理人）

**风险**：
1. **全屏三栏的数值是按 1000×720 逻辑坐标写死的**，Expand 下画布逻辑高恒 720，所以成立；
   但如果哪天改回 match=0，画布高会变，三栏会整体错位。
2. **六列台账的列宽是我按 568 可用宽收的**（规格写的 600 含内边距，实际内容宽 568）。
   如果见微要严格按 600 算，需要把内边距从 16 改成 0。
3. 右栏详情读 `TwinDetailPanel.SelectedAnchor`，**依赖详情卡组件存在**。
   场景里没有该组件时右栏恒显示告警列表（不会报错）。
