# P5-3 统计页视觉评审 REPORT 模板（见微用）

> **这是报告模板，不是任务包。** 见微填完交给主理人 → 主理人转负责人 → **负责人出任务包**。
> 依据：P00 §6.2「只有负责人能生成调度任务包」，专家不得调度其他专家。
>
> **为什么必须这么分**：见微的立场是"视觉还能更好"，他永远提得出优化项；
> 断点的立场是"我按坐标做完了"。两人直接对接 = 无限返工。
> 所以见微只出**问题清单 + 建议**，负责人判**哪些必改 / 哪些记 P2 / 哪些不做**。

## 0. 评审前置条件（缺一条就不要开始评）

| # | 前置 | 怎么确认 |
|---|---|---|
| 0-1 | 判据全绿 | 主理人提供的 `python tools/status.py` 输出里，`P5-` 前缀**全部 ✅** |
| 0-2 | 代码已生效 | 同输出的 §1 显示「✅ 已生效」 |
| 0-3 | 截图是同一版 | 截图上标注的 Unity 运行时间，晚于 dll 编译时间 |

> **为什么先卡这个**：2026-11-02 出过一次，见微按截图审了两轮，最后发现截图与代码不是同一版
> （他自己在 P5-1 §0 写「截图与当前代码不是同一版」）。**审不存在的界面，产出的是不存在的修改。**
>
> 若前置不满足，见微应**直接退回**，不要在旧截图上给意见。

## 5. 不许做的事（见微自检，逐条打勾）

- ☐ 我没有直接给断点下施工指令（只出问题清单与建议值）
- ☐ 我没有提出任务包范围之外的新功能（基线 §6.6 禁止扩需求）
- ☐ 我没有在旧截图/旧代码上评审（前置条件 §0 已满足）
- ☐ 我没有用"感觉""不太协调"这类无法施工的描述
- ☐ 我的每条建议都给了**具体数值**，断点不需再问
- ☐ 我没有为了"整齐"建议统一那些故意不统一的间距（如 §3.1 的 6/16/4/12）
