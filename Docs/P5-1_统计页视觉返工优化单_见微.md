## 1. 施工前必读（3 条，踩过就别再踩）

1. **Linear 色彩空间**：本单给的所有 alpha 是**屏幕 Δ 标定值**，禁止按 sRGB 百分比理解、禁止二次叠 alpha（`WithAlpha` 是赋值不是乘算，见 P00 §1.6 B9）。
2. **一个 GameObject 只能挂一个 Graphic**：拆图例时新增的 Text 必须各自建节点，不能复用一个矩形（B10）。
3. **构建顺序 = 背景 → 网格 → 内容**：`ApplyGrid` 不抢 sibling 顺序，后建的内容压在后面（B11）。本单新增节点一律 `TwinUIFactory.Label/Rounded` 建，别手写 `AddComponent`。

## 2. P0 · 挡住验收

### P0-1　窄态图例行结构散架：「名称 → 数值」中间掏出 56–200px 空洞

| 项 | 内容 |
|---|---|
| **现象** | 图例行现在是「色点 132 / 名称 146（宽 170，左对齐）/ 数值 320（宽 114，右对齐）」。名称只占 2 个字（约 26px），框却给到 170；数值右对齐贴死 434。结果是「电脑」和「20 台 · 29%」之间空出 200px，读起来像两列不相干的数据。同时「台数」和「占比」被拼成一个串（`20 台 · 29%`），既不是台数列也不是占比列，两种口径混在一格里。 |
| **影响** | 这一块是窄态的视觉次重心（仅次于 KPI 带）。空洞让「设备类型分布」看起来没做完，也让占比列失去列对齐的可读性。 |
| **定位** | `TwinSystemPage.cs` → `BuildStats()` 图例循环（约 686–705 行，`NDot_ / NTypeName_ / NTypeVal_`）。刷新侧 `RefreshStats()` 同名字段（约 900–925 行）。 |
| **改法（三段式，照抄坐标）** | 见下表。核心是**把「台数」拆出来紧跟名称**，占比单独成列。 |
| | 色点 `NDot_i`：x=132, y+7, 8×8, R3，颜色不变 |
| | 名称 `NTypeName_i`：x=146, w=**88**, 18 高，**左对齐**，13px TextSecondary |
| | 台数 `NTypeCount_i`（**新增**）：x=**238**, w=**56**, 18 高，**左对齐**，11px TextMuted，文案 `20 台` |
| | 占比 `NTypeVal_i`：x=320, w=114, 18 高，**右对齐**，13px TextSecondary，文案 `29%`（**去掉台数，只留百分比**） |
| **代码要点** | ① 新增 `private readonly Text[] _nTypeCount = new Text[NTypeMax];`；② 在 `RefreshStats` 里与 `_nTypeName/_nTypeVal/_nTypeSeg/_nTypeDot` **同一处** `SetActive(on)`，漏一个就会出现"有名字没台数"；③ 台数文案统一 `donut[i].Value + " 台"`，占比 `(ratio*100).ToString("0") + "%"`（整数，见 P2-1）。 |
| **验收** | ① 任意一行「电脑」右端到「20 台」左端 ≤ **8px**；② 5 行占比右端像素级对齐（误差 0）；③ 整行最右不超视口 434，不被 RectMask2D 切到半个字；④ 关掉 `其他` 段时，该行三个 Text 同时消失，不留残影。 |

**改完的图例长这样（文字示意，非截图）：**

```
● 电脑      20 台            29%
● 灯具      16 台            23%
● 门        12 台            17%
● 暖气       5 台             7%
● 其他      13 台            19%
```

### P0-2　全屏态「全楼实时功率」整块是空图，曲线只存在于最右端十几像素

| 项 | 内容 |
|---|---|
| **现象** | 02 区块 88px 高的图表区里只有 4 条水平网格，蓝色趋势线只在 x 接近右缘处出现一小段，其余全空。窄态同一张图反而是满宽平线。 |
| **根因（已定位，不是猜）** | `UpdateStatsSpark()` 的首次回填只填 **60 点**（60 × 0.2s = **12 秒**），而 `TwinSparkline` 的时间窗是 `span = Mathf.Clamp(now - t0, 1f, _windowSeconds)`（`TwinSparkline.cs` 约 287 行）——**取的是"缓冲区里最早点到现在"的真实跨度，不是固定 60s**。于是：① 首次进来 span=12s，曲线被拉伸铺满，看着正常；② `_sparkPrefilled` 一旦置 true 就再也不回填，中途切到别的页再切回来，缓冲里只剩最近几个点、但 `t0` 很旧，`span` 直接顶到 60s，近期点全挤到右侧 20%。截图正是这个状态。 |
| **影响** | 全屏态右上角是整页视觉重心。空图＝"加载失败"，答辩必被问。 |
| **定位** | `TwinFullLayer.Pages.cs` → `UpdateStatsSpark()` 回填段（约 1392–1397 行）+ `_sparkPrefilled` 字段（约 1424 行）；窄态对应 `TwinSystemPage.UpdateNarrowStats()` 约 1136–1141 行 + `_nSparkPrefilled`。 |
| **改法（4 步，全屏窄态都要）** | ① **回填点数 60 → 300**：`for (int k = 300; k > 0; k--) _statsSpark.Push(now - k * 0.2f, sum);` —— 300 × 0.2s = 60s，正好是一个满窗，和 `StatsPowerCap = 300` 对齐。 |
| | ② **新增重置方法**（全屏）：<br>`private void ResetStatsSpark() {`<br>`  if (_statsSpark != null) _statsSpark.Clear();`<br>`  _sparkPrefilled = false; _sparkLo = -1f; _sparkHi = -1f;`<br>`  _statsPowerNextAt = 0f; _statsPowerSum = 0f;`<br>`}` |
| | ③ **每次进入统计页调用**：全屏在 `SwitchTab(4)` 与 `Enter(Mode.System)` 的分支里、`_statsGroup.SetActive(true)` **之后**调用 `ResetStatsSpark()`；窄态在 `OnTabClicked(4)` / `SelectTab(4)` 里对 `_nSpark` 做同样四件事（`Clear()` + `_nSparkPrefilled=false` + `_nSparkLo/_nSparkHi=-1` + `_nSparkNextAt=0`）。 |
| | ④ **缓冲上限兜底**：`Push` 前判 `if (_statsSpark.SampleCount > 360) { _statsSpark.Clear(); _sparkPrefilled = false; }` —— 超过 72 秒就重建一次，避免长时间驻留后点数膨胀（`List.RemoveAt(0)` 是 O(n)，不要循环删）。 |
| **不要做的事** | 不要改 `_windowSeconds`（60s 是横轴标注「60s 前 / 现在」的依据）；不要为了"图好看"给曲线灌随机扰动 —— 数据恒定就该是平线，那是真实的。 |
| **验收** | ① 进统计页 **1 秒内**截图，蓝线从图表区 x=0 连续铺到 x=右缘；② 切到电力页停 30s 再切回，仍然满宽（这条是本次 bug 的直接回归测试）；③ 连续驻留 90s，曲线仍满宽、不出现右侧堆积。 |

## 3. P1 · 明显别扭（复审前一并改）

### P1-1　左轨图标是 16px 圆底 + 7px 汉字，五个图标无法区分

| 项 | 内容 |
|---|---|
| **现象** | `TwinIconGlyph.Create` 的字号是 `Mathf.RoundToInt(size * 0.46)`，`size=16` → **7px**。7 像素的「监 / 设 / 电 / 警 / 图」在 720 高画布上糊成一团，五个图标肉眼同形。 |
| **影响** | 图标不表意＝纯装饰噪音，用户只能读文字；同时左轨每行多一层视觉元素，反而降低扫读速度。 |
| **改法（推荐 A，改动最小、风险最低）** | **删图标，左轨只留文字。** ① 在 `BuildRail` 里不再调 `TwinIconGlyph.Create`，`_tabIcon/_tabGlyph` 两个数组一并删；② Tab 文字 x 由 **44 → 16**；③ 选中态改为「底 `AccentDim`(主色@0.035) + **左 2px 主色竖条**（x=0, y=8, 2×28, R1）+ 文字 `TextPrimary`」；未选中文字 `TextSecondary`。 |
| **备选 B** | 图标 `size 16→20`、字号 46%→**50%（10px）**、圆底 idle 由白@0.10 降到白@0.08。10px 汉字勉强能辨，但仍不如纯文字干净，**不推荐**。 |
| **验收** | ① 100% 缩放下 5 个 Tab 文字可直接读出，不存在小于 11px 的字形；② 选中项竖条高度 28、与文字左缘间距 14；③ 选中/未选中切换时竖条与底色同时变，不出现"条在、字没变色"。 |

### P1-2　告警 KPI 卡整卡换红底，把 6-3-1 打穿

| 项 | 内容 |
|---|---|
| **现象** | 窄态「3 告警中」整块卡片铺了暗红底（截图可见，均匀且严格落在圆角内）。代码里只改数字色（`_nKpiValue[2].color = StatusAlarm`），**卡底色另有一处赋值**——请自查 `NKpi_2` 的 `TwinRoundedRect.SetFill` 调用点。 |
| **影响** | 红色占了四张卡的 25% 面积，主色被压，且形成第 5 种表面色（另三张是同一种灰蓝底）。6-3-1 里"3"是强调色，强调不该等于"把整块区域涂成强调色"。 |
| **改法** | 卡底**恒为** `CardTop / CardBottom`；红色只出现在三处：① 卡内左侧 **2×28** 竖条（x=0, y=12, R1）`StatusAlarm`；② 数值 28px `StatusAlarm`；③ 标签右端一个 **4×4** 圆点 `StatusAlarm`。红色面积从 25% 降到 **3%** 以下。 |
| **验收** | ① 四张 KPI 卡底色取样 Δ ≤ 2（`CardTop` 与 `CardBottom` 的纵向渐变允许）；② 无告警时竖条与圆点 `SetActive(false)`，卡与其它三张完全同貌。 |

### P1-3　donut「其他」灰比任何一段都亮，反抢第一眼

| 项 | 内容 |
|---|---|
| **现象** | `DonutColor(4)` 用 `StatusUnknown (0.35, 0.38, 0.45)`，亮度高于 `ChartSeq4 (0.10, 0.35, 0.47)`。深色底上灰块是整圈最亮的一块，而它代表的是"其余类型"这种最不重要的聚合项。 |
| **影响** | 读者第一眼落在"其他"上，误判结构。 |
| **改法** | `DonutColor(4)` 改为 **`(0.29f, 0.31f, 0.36f, 1f)`**（不用 token，直接常量，注释写明"其他=聚合项，亮度必须低于 ChartSeq1–4 任意一段"）。窄态 `NDonutColor(4)` 同步改，两处必须逐位相等。 |
| **验收** | 取 5 段中心色算亮度（0.2126R+0.7152G+0.0722B），「其他」为 5 段中**最低**。 |

### P1-4　底部两处时间戳重复；工具行「数据源」是假选中

| 项 | 内容 |
|---|---|
| **现象** | ① 统计页页脚右段是「更新 16:45:40」，同一屏右下角还有「v0.9 · 16:42:46」——两个时间戳。② 工具行「数据源」长期带一条蓝色下划线，但它是个**动作**（打开数据源设置），不是"当前所在页"。 |
| **影响** | 时间戳重复是主理人明确反感的"信息重复"；假选中会让人以为"数据源"是一个页面。 |
| **改法** | ① `TwinFullLayer.cs` 约 223 行：`v.text = "v0.9 · " + DateTime.Now.ToString("HH:mm:ss");` → **`v.text = "v0.9";`**；时间由统计页 `FFootR` 单独承担（它 0.5s 刷一次，本来就准）。② `TwinDrawer` 的 `SelectTool(0)`：**不保留持久下划线**——`Underline` 只在 `pointerDown` 期间显示（按下 120ms 淡出），常态隐藏；`_toolUnderlineObjects` 保留，只改显隐时机。 |
| **验收** | ① 全屏统计页底部只有一处时间（`更新 HH:mm:ss`）；② 工具行四项在常态下均无下划线；③ 点击「数据源」有 120ms 的按下反馈，不改变任何持久态。 |

### P1-5　折线是"一条水平线"，读起来像没数据

| 项 | 内容 |
|---|---|
| **现象** | 全楼功率真实值恒定，`span = max(hi-lo, max(0.5, hi*0.05))` 的自适应量程把 ±0.02 kW 的波动放大后仍接近平线。技术上是**正确**的（数据就是稳），但视觉上等于"空图"。 |
| **影响** | 评委看不出"这是稳定的曲线"还是"这是没接数据"。 |
| **改法** | 在「60s 前 / 现在」两标之间加一句**居中 11px `TextMuted`** 标注，仅当 `(hi - lo) < 0.05 kW` 时显示：<br>文案 `波动 ±0.02 kW · 运行稳定`（数值 = `(hi-lo)/1000` 保留两位）。<br>窄态放 y=208 同行居中（x=120, w=200）；全屏放 y=384 同行居中（SRightX+120, w=200）。 |
| **验收** | ① 数据恒定时曲线区有一句解释文案，且不与「60s 前 / 现在」重叠（三者在同一行左右中分布）；② 一旦波动超过 0.05 kW，这句自动隐藏。 |

**末项配平写法（两态通用，别自己发明）：**

```
// 前 n-1 项四舍五入，最后一项吃掉误差
int acc = 0;
for (i = 0; i < n - 1; i++) { p[i] = Mathf.RoundToInt(ratio[i] * 100f); acc += p[i]; }
p[n - 1] = 100 - acc;
```
