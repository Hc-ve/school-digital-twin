## 零、结论先行

1. **v3 的「平面小方片撒在叶卡上」不是参数问题，是形态问题。** 方片和 alpha 叶卡同层，侧视必被叶卡挡住，放大必浮成白雾。320 片 / 0.9m 这一版继续扫参，最多是在"看不见"和"白雾"之间反复。
2. **真实世界的雪不是"白点"，是"有厚度的团块 + 沿枝上缘的雪脊"。** 这两样都必须有体积，才在任何视角成立。
3. **推荐路线：几何雪团（低模不规则椭球）替代平面片。** 依据是 SIGGRAPH 2000 的积雪建模论文（雪在近距针叶上会形成"桥接与团块"，是有厚度的隐式体，不是贴片），也是所有写实雪景的共通形态。
4. **材质级积雪花（法线朝上遮罩）在本项目不是首选**：地形树材质是共享资产、Terrain 批渲染吃不到材质属性块，改了就是资产污染——这一点 v3 调研已经证实，本文不推翻。
5. **付钱插件（Global Snow）直接排除**：项目红线"不引第三方包"，且它是屏幕空间后处理，会把所有朝上像素变白，与本项目既有屋顶雪壳重复叠加。

## 一、真实形态拆解（照 6 张实拍逐条对）

| # | 观察 | 对应参考图 |
|---|---|---|
| 1 | 雪是**厚团块**，不是薄白层。团块有明确轮廓与厚度，能看到"堆起来"的圆鼓边缘 | ref02、ref05、ref06 |
| 2 | 雪只挂**上表面**。枝条/叶簇的下表面仍是深色，暗部与雪形成强对比 | ref01、ref03、ref05 |
| 3 | 团块**不连续**。团与团之间有暗缝，缝里能看到深绿枝叶或褐色枝干，缝隙占比约 25~40% | ref02、ref05 |
| 4 | **越靠外、越靠上，雪越厚**。冠内与冠底被上层挡住，雪明显少 | ref01、ref03 |
| 5 | 侧视时能看到**沿枝上缘的白色雪脊**（细长条），这是轮廓"白边"的来源 | ref03、ref04 |
| 6 | 背光面雪偏**蓝灰**，向光面亮白。不是纯白 | ref02、ref06 |
| 7 | **Y 形分叉处积雪最多**，横向枝条比垂直干更容易挂住 | ref04、ref05 |
| 8 | 远处（>40m）雪团合并成连续白色块面，只剩轮廓；近看才有结构与缝隙 | ref01、ref03 |
| 9 | 树冠整体轮廓被雪"抬"了一圈——**边缘的雪比内部密** | ref03、ref05 |

**一句话判据**：站在树侧面 45°，要能看到"白团鼓出来 + 团间暗缝"，不需要俯视也能读出来。**v3 现在做不到这一条**——它只有俯视才成立。

## 二、四条技术路线对比

| 路线 | 做法 | 真实性 | 本项目可行性 | 判定 |
|---|---|---|---|---|
| **A 材质混合**（法线朝上遮罩） | 自写 shader：世界法线·up 夹角 → 积雪量混合 albedo/法线 | ★★★★ | 地形树材质是共享资产；Terrain 批渲染不认材质属性块；要改就得给每棵树独立材质 | **不做**（资产污染） |
| **B 屏幕空间雪** | Image Effect 读 `_CameraDepthNormalsTexture`，朝上像素插值成白 | ★★ | 会把所有朝上像素变白（地面、屋顶、桌面全中）；本项目屋顶已有雪壳，会叠加；alpha 卡的深度法线不准 | **不做**（叠加冲突） |
| **C 几何雪团**（推荐） | 在叶卡上表面生成**有体积的低模雪团** + 沿缘雪脊，合并网格 | ★★★☆ | 纯运行时程序化 mesh；复用现有合并网格管线；不碰共享材质 | **采用** |
| **D 换冬季树模型** | 低模锥/球冠树 + 雪材质 | ★★★★★ | 形态最可控，但要换掉 35 棵地形树的原型，工作量与观感风险都大 | **备选**（C 不达标再上） |
| ~~E 付费插件~~ | Global Snow 等 | — | 违反"不引第三方包"；且是屏幕空间 | **排除** |

## 三、推荐方案 C 的详细设计

### 3.1 为什么几何体能成、平面片不能成

- **平面片**：与叶卡同层 → 侧视被外层叶卡遮死；放大后片与片之间没有厚度差 → 读成白雾。
  这是 v3 三轮调参（0.22→0.45→0.95m、悬浮 0.12→0.34m）都走不出的死循环。
- **几何体**：有体积 → 任意角度都能看到"鼓起来"的圆鼓面 + 底部的暗缝；且不透明材质不参与 alpha 排序，不会被叶卡"吃"掉。

### 3.2 雪团几何规格

| 项 | 取值 | 理由 |
|---|---|---|
| 单体形状 | 低模不规则椭球（12~20 三角，顶点随机扰动 ±15%） | 有体积、便宜、不像球 |
| 竖向压扁 | Y 轴缩放 0.35~0.5 | 雪是"堆"不是"球" |
| 尺寸分布 | **幂律**：70% 为 0.35~0.7m，25% 为 0.8~1.1m，5% 为 1.2~1.6m | 真实雪团大小极不均匀；全是同尺寸最假 |
| 单棵数量 | 28~45 个（按树高/冠幅微调） | 35 棵 × 40 × 16 tri ≈ 22k tri，可接受 |
| 位置 | 叶卡**顶部区段**顶点 + 沿冠心向外偏移 | 冠顶多、冠内少（第 4 条观察） |
| 悬浮 | 贴住叶卡表面 + 0.05~0.12m | 不浮空，不埋进去 |
| 朝向 | 随机偏航 + 沿主风向倾斜 ≤ 15° | 有风时雪偏一侧 |
| 附加：雪脊 | 沿叶卡最高边生成 3~5 段细长条（宽 0.12~0.18m） | 侧视轮廓的"白边"来源（第 5 条观察） |

### 3.3 与现有系统的接法（不重写）

- 复用 `SnowOnTrees` 已有的 **`protoCards` 叶卡模板缓存**（原型 prefab 根空间 + 法线 + 面积），只是把"撒方片"换成"生成团块"。
- 复用已有的**合并网格 + 单 draw call** 管线与 `_GlobalSnow` 雪量驱动（雪量爬升时团块跟着长出来）。
- 材质：**必须用不透明雪材质**，不复用 `CampusUI/SnowGround` 的径向渐隐遮罩（`_MaskOff=0` 那张遮罩就是"雾感"的来源之一）。需要核一下该 shader 是否支持关闭遮罩的不透明模式；不支持则新增一个极简雪材质（纯色 + 噪声法线 + 与雪壳同色 `_SnowColor`）。
- 地形树实例的 `rotation / widthScale / heightScale` 变换照旧要做（v2 忘做导致矮树雪浮空，教训在案）。
- 独立树（Tree1/2/3 Clone）：仍走同一套团块生成，与 `SnowOnRoofs` 的树卡排除互不影响。

### 3.4 必须保留的既有红线

- 雪壳**不带 Collider**（物理射线穿透，防角色浮空）
- 雪壳材质名不同步进屏幕快照链（防幕布被盖）
- 不碰灯光常量、不加灯（`totalLights=404` 不变）
- 不改共享材质资产（地形树原型材质只读）

## 四、实施步骤（下一步照这个走）

1. 停 Play → 读 `SnowOnTrees.cs` 现有叶卡缓存结构（已读，字段在 49~72 行）
2. 新增 `BuildFoliageLumps()`：叶卡顶点 → 幂律尺寸 → 椭球模板（预生成 3~4 种扰动版本复用）→ 合并进同一 mesh
3. 新增雪脊生成（同 mesh，独立材质槽或同材质）
4. 材质：确认 `SnowGround` 是否有不透明模式；无则加一个极简 `SnowClump` 材质（程序化，零图片资源）
5. `refresh_unity` → 核 `Assembly-CSharp.dll` 时间戳晚于最后 `.cs`
6. 进 Play 拍**三张固定机位**：俯视 60°、侧视 45°、远景 40m（同机位同档位，与 `Docs/QA/reference/tree_snow/` 对照 A/B）
7. 自评四条硬指标，不达标就改参数不换方案
8. 判据全绿 → 回执 → 提交

### 验收硬指标（量化 + 视觉双栏）

| 项 | 指标 |
|---|---|
| 侧视可读性 | 侧视 45° 能看出白团轮廓与团间暗缝（**这一条不过，方案就是不成立**） |
| 覆盖率 | 视口内树冠白色像素占比 55~70%，不超过 75%（超了就是"棉花糖"） |
| 暗部保留 | 冠底/枝下暗色可见，暗像素 ≥ 25% |
| 性能 | 单树 tri ≤ 1200；合并后新增 draw call = 1 |
| 一致性 | 雪团色与屋顶雪壳同色；夜里不被 Bloom 吃成发光块 |
| 回归 | 角色落地 / 室内判定 / 幕布链 / 灯数 404 四项全过 |

## 五、风险与已知坑

| 风险 | 应对 |
|---|---|
| 团块太大 → 变棉花糖 | 幂律分布 + 硬上限 1.6m + 覆盖率闸门 |
| 团块太小 → 又回到"星点" | 下限 0.35m，且数量按冠幅调 |
| 雪团埋进叶里看不见 | 贴面 +0.05~0.12m，且只取"冠顶区段"叶卡（v3 已解决过这个坑） |
| 不透明材质与半透叶卡排序打架 | 雪团走不透明队列；不与叶卡同层重叠（外扩 0.1m 以上） |
| 夜里雪团发灰不白 | 复用雪壳的 `_SnowColor` 与环境光口径，别自己调色 |
| 又一次"改完没验证" | 三张固定机位截图必须落盘，禁止只报读数 |
