| 5 | `m_ProbeAnchor` 显式置空（`objectReference: {fileID: 0}`） | 4 | Unity 序列化产物，**等效默认值** |

### 2.1 第 5 项要说清楚

第一次保存时这里写的是 `{fileID: 823652957}`（指向 Floor2 自己的 Transform），是拖拽时 Unity 顺手写的。
清空 Anchor Override 后变成 `{fileID: 0}` —— **Unity 记录的是「有覆写、值为空」，不会把这条记录删掉**。

- **功能上**：`{fileID: 0}` = `null` = 从未设置过，与默认行为完全一致
- **序列化上**：这条记录会一直留着，再清一次也去不掉（除非 Revert 整个组件，那会连 Material 覆写一起回滚，风险更大）
- **结论**：23 行是这条路径能达到的最干净状态

### 2.3 挂载对象的偏离

规格写「挂在场景里任意一个常驻 GameObject 上（**如 [TwinRuntime]**）」。

**但 `[TwinRuntime]` 在场景里不存在** —— 它是 `TwinRuntime.Ensure()` 运行时创建的（`RuntimeInitializeOnLoadMethod` 之后），场景 YAML 里 grep 不到，也就挂不上组件。

实际挂在 **`TwinPlayer`**（场景常驻、有实例）。功能等价：两者都是场景加载时就存在的常驻对象，`Awake()` 时机相同。

**可能踩的坑（提前说）**：

截图里编辑器底部有一条黄字：

```
Lighting data asset 'LightingData' is incompatible with the current Unity version.
Please use Generate Lighting to rebuild the lighting data.
```

这条**先不动**（重建烘焙不可逆，是打光的活）。判断依据：打光诊断时能读到 `lightmapIndex = 6`、图集亮度 0.2576 正常，说明 lightmap 数据实际可用，这条大概率是版本检查的宽松提示。

**但如果进 Play 天花板还是黑的**，按这个顺序查：

1. Console 有没有 `[P30] ... target 未拖引用`？有 → 引用丢了，重新拖
2. `TwinPlayer` 上组件是不是 `m_Enabled: 1`？场景里是 1
3. 组件是否真的执行了？临时在 `Awake()` 加一行 `Debug.Log(target.lightmapIndex)` 看是不是变 -1
4. 如果值已经是 -1 但还是黑 → 说明黑的不止是 lightmap，那条 `LightingData incompatible` 警告就是下一个线索，要交回打光
