### 2.2 为什么拿不到：三次尝试与实测证据

截图必须满足两个条件：**Unity GUI 进程活着** + **Play 模式下 GameView 在渲染**。  
本项目 UI 是 `Screen Space - Overlay` Canvas —— Overlay 不经过相机渲染，  
无法用 `Camera.Render` 到 RenderTexture 捕获，只能走 `ScreenCapture`（读屏幕）。所以必须有真实窗口。

| # | 尝试                    | 命令                                                 | 结果                                                                                                                                           |
| - | --------------------- | -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 1 | GUI + `-logFile`      | `Unity.exe -projectPath ... -logFile Temp/gui.log` | 进程存活约 6 分钟后 exit 0，**`Temp/gui.log` 从未被创建**；默认 `Editor.log` 也未更新（停在 17:36:30）。根因：`Temp/UnityLockfile` 残留（前一次 `-quit` 强制退出没清锁），GUI 启动被单实例检测挡住 |
| 2 | 清锁后 GUI + `-logFile`  | 同上                                                 | 清锁后重试，进程存活 5 分钟 exit 0，**仍然零日志**                                                                                                             |
| 3 | 清锁后 GUI 不带 `-logFile` | `Unity.exe -projectPath ...`                       | 进程即起即退，**默认 `Editor.log` 全程停在 17:36:30**（观察 160 秒）                                                                                           |

补充尝试 4：**batchmode + 自动采集**  
`Unity.exe -batchmode -projectPath ...`（不加 `-quit`，靠 `[InitializeOnLoad]` 的 `EditorApplication.update` 驱动）  
→ 工程加载完成（日志 `[Project] Loading completed in 15.560 seconds`）后**再无任何输出**，  
采集器一次都没被触发。原因是 **batchmode 不跑编辑器 update 循环**，`[InitializeOnLoad]` 挂上去的  
回调没有机会执行。

当前会话**无法启动 Unity GUI**（三次均进程即退、零日志），而截图**只能**由 GUI 渲染产生。  
这是执行环境的限制，不是代码问题 —— 采集脚本本身已随 `Assembly-CSharp-Editor.dll` 编译生效。
