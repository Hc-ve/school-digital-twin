1. `tr.parent.name == "DayLightsExterior"`

## ② A2 TwinId 方案 + 点位清单

### ID 方案

```
TwinId 格式： Exterior/Lamp/RoadLamp_<三位序号>
例：         Exterior/Lamp/RoadLamp_001
```

| 字段 | 取值 | 理由 |
|---|---|---|
| Zone | `Exterior` | 与室内 `Class2-1` / `Corridor1` 等完全分开，一眼可辨 |
| Category | `Lamp` | **刻意不用 `Light`**。室内灯管已用 `Light`（`TwinDeviceModel.cs:181` 定义了 Power/SetPower/LampFail，:545-593 还有一张硬编码室内灯 TwinId 表）。用 `Lamp` 可以从根上避免撞车，也便于将来给路灯单独定义模型 |
| Name | `RoadLamp_<序号>` | 沿用场景对象前缀，外包可肉眼对应 |
| DisplayName | `室外路灯 001` 等 | 面向管理系统的中文可读名 |
| Segment() | `Exterior/Lamp` | `TwinAnchor.Segment()` 自动取前两段，无需额外配置 |

### 与现有锚点的冲突检查

| 现有锚点 | TwinId | 本方案是否冲突 |
|---|---|---|
| `TwinMarker_ClassComputer_Light_Main_01` | `ClassComputer/Light/Main_01` | ❌ 不冲突（Zone+Category 均不同） |
| `TwinPoint_BAK_Class2-1_Light_Main_01` | `Class2-1/Light/Main_01` | ❌ 不冲突 |
| `TwinMarker_ClassDirector_Light_Main_01` | `ClassDirector/Light/Main_01` | ❌ 不冲突 |
| `TwinMarker_ClassTeachers_Light_Main_01` | `ClassTeachers/Light/Main_01` | ❌ 不冲突 |

当前场景 `TwinAnchor` 组件共 **76 个**，无一使用 `Exterior/Lamp/*`。

### ⚠️ 已知风险：`Lamp` Category 暂无设备模型

`TwinDeviceModels.For()`（`TwinDeviceModel.cs:178` 的 switch）**没有 `case "Lamp"`**，
会走 `default` 分支返回空模型 → 卡片上不会出现控制区、状态胶囊可能异常。

**两个选项，需负责人裁决**（见 §5 问题 1）：
- **选项 A（推荐）**：Category 改用 `Light`，Zone 保持 `Exterior`。可直接复用现成模型，零代码改动，TwinId 仍不与室内撞（`Exterior/Light/...` vs `Class2-1/Light/...`）。
- **选项 B**：保持 `Lamp`，由外包在 `TwinDeviceModels.For()` 增加 `case "Lamp"`，复制 `case "Light"` 的模型定义（Power 0~120W / SetPower / LampFail）。

## ③ 锚点落地步骤（阶段 B）

### 3.1 挂哪个对象

**挂到 A1 表格里的路灯根节点**（`DayLightsExterior` 的直接子节点），不要挂到 `LampGlass` / `LampPillar` 等 FBX 内嵌部件上。
理由：根节点位置就是灯杆基座（y=-0.50），变换稳定；部件节点会随美术调整改名。

### 3.2 两种落地方式（需负责人裁决，见 §5 问题 2）

| 方式 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 场景手动挂（当前现状）** | 在 Inspector 里逐个给 100 个根节点 Add Component `TwinAnchor`，填 4 个字段 | 零代码风险，当场可见 | 100 次手工操作易漏易错；场景文件产生大 diff |
| **B. 自举脚本（我推荐）** | 新建 `RoadLampAnchorBootstrap.cs`，用 `[RuntimeInitializeOnLoadMethod(AfterSceneLoad)]` 遍历 `DayLightsExterior` 下 `RoadLamp*`，动态 `AddComponent<TwinAnchor>()` 并填字段 | 可复现、零场景改动、数量天然与场景一致、答辩前改灯不会漏锚点 | 锚点不在 Editor 静态可见，调试需进 Play |

**我的建议：选 B（自举脚本）。**
理由与 `TwinWeatherBootstrap` / `TimeCycleDirector` 的既有范式一致（项目已验证可行）；
100 盏手工挂极易出错，而自举天然保证"场景里有多少盏就有多少个锚点"；
且本包铁律是零场景改动，自举是唯一不碰 `.unity` 的路径。

自举脚本骨架（外包可直接用）：

```csharp
using UnityEngine;
using SchoolTwin.Twin;

namespace SchoolTwin.Twin
{
    /// <summary>室外路灯锚点自举：遍历 DayLightsExterior 下的 RoadLamp* 根节点，动态挂 TwinAnchor。</summary>
    public sealed class RoadLampAnchorBootstrap : MonoBehaviour
    {
        [RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterSceneLoad)]
        private static void Mount()
        {
            Transform root = GameObject.Find("DayLightsExterior")?.transform;
            if (root == null) { Debug.LogWarning("[P44] 未找到 DayLightsExterior，跳过路灯锚点"); return; }

            int n = 0;
            foreach (Transform child in root)
            {
                if (!child.name.StartsWith("RoadLamp", System.StringComparison.Ordinal)) continue;
                n++;
                var a = child.GetComponent<TwinAnchor>();
                if (a == null) a = child.gameObject.AddComponent<TwinAnchor>();
                a.Configure(
                    "Exterior/Lamp/RoadLamp_" + n.ToString("000"),
                    "室外路灯 " + n.ToString("000"),
                    "Exterior", "Lamp");
            }
            Debug.Log("[P44] 室外路灯锚点自举完成，共 " + n + " 盏（期望 100）");
        }
    }
}
```

> ⚠️ 上面 `a.Configure(...)` 是**示意接口**。阶段 A 未改动 `TwinAnchor`，请先确认它是否有公开的批量配置方法；
> 若没有，可用反射写私有字段，或由负责人裁决是否给 `TwinAnchor` 加一个 `Configure()` 公开方法。见 §5 问题 3。

### 4.3 指标建议

参考 `MockDeviceAgent.cs:423/479/647` 的灯具处理与 `TwinDeviceModel.cs:181`（Light）/:292（Projector）：

| 指标 | 类型 | 量程 | 建议值 | 说明 |
|---|---|---|---|---|
| `Power` | Float | 0~120 W | 开灯 42W / 关灯 0W | 与室内灯管同口径（`TwinDeviceModel.cs:183` 警告线 110） |
| `Status` | Enum/Bool | — | 正常 / 故障 | 可复用现有状态判定，不必新造 |
| `LampHours` | Int | 0~10000 h | 1240（保留量） | **关键**：`MockDeviceAgent.cs:479/649` 明确"关机也保留、不归零"。路灯同理，关灯后小时数应继续保留 |

**不要用 `SetPower` 动作驱动路灯**：室外灯由昼夜循环控制（`TwinWeatherBridge.ApplyHour(23,true)`），
不是玩家手动开关。若外包要加联动，建议把路灯 Power 绑定到 `EnvironmentState.timeOfDay`，
而不是加一个可被玩家点的开关。
