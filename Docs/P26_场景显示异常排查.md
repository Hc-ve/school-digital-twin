# P26 场景显示异常排查：右侧墙壁发黑 + 场景里出现"网格"

> 报障（2026-10-28）：机房右侧墙壁材质像丢了、整体发黑；场景里出现一块此前没有的"网"（后经确认是 Unity 场景视图自带的地面网格）。

## 〇、最终结论（2026-10-28 09:34 结案）

**两条都不是缺陷，不需要修。**

| 现象 | 结论 |
|---|---|
| 那面墙发黑 | **原始资产就是深色墙**（教室正前方的那面墙）。用户在**未迁移的原项目** `E:\Unity Projects\School` 里打开同一间教室，视觉效果完全一致。 |
| 场景里出现"网格" | **Unity 场景视图的 y=0 地面网格**，编辑器显示物，**不进打包版本**。地面也在 y≈0，共面 z-fighting 导致网格透出来。 |

排查过程中排除掉的所有可能原因（位置被拖歪 / 材质引用断裂 / 资源没加载 /
幕布着色器贴错地方），以及"怎么区分**真·空**还是**材质损坏**"的判断方法，
留在下面，以后再遇到类似的"某块地方不对劲"可以直接复用。

关键判据，记住这三条：

1. **点选不到** = 那里没有 Renderer = 没有几何 → 是"空"，不是"材质坏"
2. **y=0 网格能在那里显示** = 那里能看穿（网格只在没有不透明几何遮挡时才露出来）
   → 和第 1 条互相印证
3. **材质坏**会表现为：粉色（shader 丢失）/ 纯黑但**点得到**（材质被换成黑的）/
   隐形但**Hierarchy 里有**（`Renderer.enabled = false`）

### 1.2 "网格"是什么

是 **Unity 场景视图自带的地面网格**，画在 **y = 0 平面**上。

- 它是**编辑器显示物**，不进打包版本，跟渲染无关。
- 之所以能看见，是因为**房间地面正好在 y = 0**，网格与地面**共面 z-fighting**，于是网格透过地面显示出来。相机压低、贴近地面时最明显。
- 想让它消失：场景视图右上角 **`Gizmos` 下拉 → 取消勾选 `Show Grid`**（2022.3 在 Gizmos 按钮同一排的下拉里）。

**判断是否真的被移动过**（万一地面被挪了）：选中房间根对象看 Inspector 的 Y；或跑下面的一键体检，它会打印根对象世界坐标。

### 1.3 「墙壁发黑」几个候选原因的排查结论

> 结案后回看：① 是真相；②③④ 当时没有排除干净，但最终都不是原因。
> 保留这段是因为里面的判据可以复用。

### ① 那其实是**投影幕布**，不是墙

`ProjectorScreen01` 的实际尺寸（来自运行时日志）：

```
屏幕平面 3.11 × 2.12 m（比例 1.472）
中心 (-11.54, 2.06, 38.01)
法线 (-1.00, 0.00, 0.00)
```

y 从 1.0 到 3.12 —— **几乎顶天立地、贴着墙的一块大板子**，从玩家视角看就是"墙的一部分"。

它有两个材质槽（预制体里）：`PlasticWhite1`（白布）+ `PlasticBlack1`（边框，`_Color = 0.176`，接近黑）。
P26 运行时会**把两个槽都换成 `SchoolTwin/ScreenOnModel`**。

要注意的两种黑：

- **投影仪从未开过机** → 材质还是模型原样子，白布 + 黑边框，正常。
- **投影仪开过又关** → 走 `_OffColor`（下限 0.62，浅灰白），也不该是纯黑。

如果看到的是**纯黑、边缘发柔**的大块 → 那更像是③。

### ② 幕布着色器 —— **这一条可以排除**

一开始最怀疑是 `TwinScreenOnModel` 被贴到了墙上。看代码能否掉：

```hlsl
float3 c = lerp(offCol, video * _EmissionColor.rgb, on * inside);
```

- `on = 0`（关机）→ 输出 `offCol`，下限 0.62，**浅灰白**
- `on = 1` 但 `inside = 0`（屏幕矩形之外）→ `t = 0` → 仍然输出 `offCol`

**这个着色器在任何分支下都输出不了纯黑**，最多把一块面变成浅灰。
所以"墙变黑"不是它造成的。

### ③ 实时阴影：一块柔边暗斑

截图里那块黑的边界是**糊的、渐变的**，不是硬几何边 —— 更像**阴影**，不像材质。

- 场景原本是**全烘焙**光照（2017 年的 lightmap），烘焙光不产生实时阴影。
- 一旦该区域出现**实时灯**（P24 灯锚点、P26 投影聚光灯…），低分辨率阴影贴图打在
  大网格墙面上就会出现这种"大面积、边缘发虚"的暗块。

判断：`Window → Rendering → Lighting` 切 `Realtime` 看该区域有没有实时灯；
或临时关掉几盏灯，看暗斑是否跟着变。

### ④ 反射探针的烘焙 cubemap 在该区域是黑的

场景里有 **42 个 Reflection Probe**（每个房间一个）。
烘焙 cubemap 缺失时，探针盒范围内较光滑的表面会被乘上黑色反射，
同样表现为**边界柔和、随探针盒边缘渐隐的暗斑**。

判断：选中那片墙附近的 Reflection Probe，看 Inspector 有没有 `Baked` 贴图；
或把 `Type` 临时改成 `Realtime` 对比。

> ①③④ 都会让"一整块面变暗"，靠截图分辨不了。
> **最快的办法：在场景视图里直接点那块黑**，看 Inspector 选中了什么对象 —— 一次点击定位。

新增菜单（已加入工程）：


跑完看 Console，会打印：

```

---- 根对象世界坐标 ----
  SchoolScene  pos=(0.000, 0.000, 0.000)  scale=(1.000, 1.000, 1.000)
  ...
---- ★ 真正断裂的材质（槽为空）：0 个 ----
---- ★ shader 丢失：0 个 ----
---- 使用 P26 幕布着色器的 Renderer：N 个 ----
  ClassComputer/.../ProjectorScreen01  [SchoolTwin/ScreenOnModel]  bounds=(3.11, 2.12, 0.10)
  ★ 可疑：不在幕布上 / 尺寸过大      ← 有这行就是②
---- 包围盒 > 30m 的巨大物体：0 个 ----
```

- 出现 `★ 可疑` → ②，把那个 Renderer 的材质覆盖还原即可
  （`Tools/P26/② 还原幕布材质到预制体默认值`）。
- 没有可疑项、但仍有暗斑 → ③，选中那片墙附近的 Reflection Probe，把 `Type` 改成 `Realtime` 或重新烘焙光照。
- `场景是否被改过(未保存): 是` → 见下面第五节。

## 三、如果编辑器里有未保存改动

磁盘上的场景文件是**完好的**（与最后一次提交一致），所以最省事的修复是**丢掉未保存的改动**：

1. `File → Open Scene` 重新打开 `SchoolSceneDay`，弹窗选 **Don't Save**；
2. 或者 `Edit → Undo` 一路退回到"看起来正常"的那一步。

**不要直接 Ctrl+S** —— 那样会把异常状态写进文件，反而破坏现在这份完好的基线。

## 四、顺带发现的一个真 bug（与本问题无关）

`Assets/_Project/ScriptableObjects/PPS_Bloom.asset` 的 `settings` 里是一个**空引用**：

```yaml
settings:
- {fileID: 0}
```

也就是说 `[PPS] Bloom` 这个 Volume 的 Profile 里**没有任何 Bloom 覆盖项**，
Bloom 目前是**静默失效**的（和 2026-10-26 修过的那次是同一个病）。
修复：点菜单 `P25 光晕/① 一键配置 Bloom` 重跑一次。


**⇒ 那面墙不是"材质丢了"，是那块地方真的没有几何。**

用户在场景视图里点那片黑，**选不中任何对象** —— 这是最直接的证据：
没有 Renderer 就没有可点选的碰撞体/包围盒。

而"网格"能显示在那片区域，本身就是"这里能看穿"的证据：
Unity 的 y=0 地面网格只有**没有不透明几何挡住**的地方才会露出来。

游戏视图里那块"糊边黑影" = 看穿墙之后看到的**天空盒/背景**（天空盒是渐变，
所以边界发虚，不是硬几何边）。

### 另外发现的两个真·空材质（与本问题无关，但该修）

`SchoolScene/Interior/SportClassProps/Door02_1` 下的 `glass` 和 `door02_1`
两个 Renderer 的材质槽 0 是空的 —— 这扇门在游戏里是**隐形**的。
补回一个材质即可（玻璃用 `Glass*`，门板用 `Wood*`）。
