## 二、为什么会错（我的判断失误）

### 2.1 抽屉锁死 720 —— 这是「按钮消失」的直接原因

主理人窗口 `Screen = 1069×654`，`scaleFactor = 1.064`，所以画布只有 **1004 × 614**。
我把抽屉高度写死 720 并垂直居中 → **上下各溢出 53px**：

- 顶部溢出 53 → 头部 96 高被裁掉上半 → **标题、关闭 × 看不见**
- 底部溢出 53 → 工具行 80 高被裁掉下半 → **数据源 / 录制 / 帮助 / 设置 四项看不见**
- 关不掉抽屉 → 抽屉一直开着 → 触发钮按设计保持隐藏 → **「总控面板那个按钮」也没了**

三个症状是**同一个根因**，不是三个独立 bug。

### 2.2 我错在哪

我看到 `page.rect.height = 544` 就认定"容器对了、问题解决了"，但**没有检查抽屉本身有没有出屏**。
`rect.height = 544` 恰恰是抽屉 720 高才成立的 —— 它既是"内容区对了"的证据，
也同时是"抽屉比画布高 106px"的证据。我只看了前一半。

**教训**：断言一个容器尺寸"正确"之前，先确认它没有超出父容器。否则改对的和改坏的会互相掩盖。

### 2.3 小地图 —— 我改的方向就不对

我在 64×64 密度扫描上看到 Floor2 内容只占 51.6%×40.6%，就认定"贴图内容小、要裁"。
但主理人 play 看到的是**位置不对**，不是"内容小"。
说明我裁掉的那块**不是"空白边"，而是地图的真实范围** —— 裁剪后玩家位置映射整体偏移，图就错位了。

密度扫描只能证明"这块比较暗"，不能证明"这块没有意义"。
二层图外围那些深色区域很可能是**走廊/挑空/非教室区**，本来就该在图上。

**结论：这张表不该加。已整文件回退。**

## 三、当前 1069×654 下的预期表现（回退后）

回退后抽屉跟随画布，Content 高度 = 614 − 96 − 80 = **438**，而 L1 内容按 544 排到 504。

| 项 | 值 |
|---|---|
| 画布 | 1004 × 614 |
| 抽屉 | 1004 宽 × **614 高**（完整可见，不再出屏） |
| 内容区 | **438**（< 544） |
| L1 第 4 条动态下沿 | 484 → **超出内容区 46px** |
| 表现 | 被 `_content` 的 `RectMask2D` **裁掉**，看不见，但**不会压在工具行上** |

也就是说：**按钮回来了、小地图恢复原样，但 1069×654 下 L1 底部约 46px 内容会被裁。**

这是 R7 的必然结果，不是代码 bug：`CanvasScaler match=0` 只按宽度缩放，
画布高 = `screenH × 1000 / screenW`，**只有窗口是 1000:720 比例时画布高才等于 720**。
1069×654 的比例是 1.635，不是 1.389。

**三条路（需负责人定，我不擅自动手）**：

| 方案 | 做法 | 代价 |
|---|---|---|
| A. 改窗口比例（最省事） | GameView 设成 **1000×720**（Fixed Resolution）或 1280×921 | 零代码；答辩机也按这个比例设 |
| B. 改 CanvasScaler.match = 1 或 0.5 | 画布高锁 720，宽度随窗口溢出 | **改场景组件**，影响全项目所有 UI，需重新走查 |
| C. 抽屉内整体缩放 | 抽屉根挂一个 scale = min(1, canvasH/720) 的层 | 改 UI 架构，动效/坐标全受影响，风险最高 |

我建议 **A**。B/C 都是打包阶段的活，现在动会把已通过的布局全部推倒重验。

## 四、探针的两处误报（已修，未编译）

主理人截图里 `[P29-3.5] 布局体检` 的那些 ✘ 有一部分是**探针自己算错**，不是面板错：

| 误报 | 原因 | 修法 |
|---|---|---|
| `抽屉高 = 544.0 期望 720.0 ✘ 抽屉没锁死 720` | 层级少走一层：`homeRoot.parent` 是 **PageStack**，`content.parent` 拿到的是 **Content**（544），不是抽屉根 | 显式区分三层 `pageHost / content / drawerRoot` |
| `Canvas.rect = 220.0×68.0` | `FindObjectOfType<Canvas>` 命中的是某个**子 Canvas**，不是主画布（主画布是 1004×614 量级） | 改为取**面积最大**的 Overlay Canvas |
| 断言项本身 | 抽屉已改为跟随画布，"是否锁死 720"不再是有效断言 | 改成断言 **内容区高是否 = 544**，不足时明确标注"画布高 ≠720，属 R7" |

改后探针会报：
```
内容区高（世界尺度）= 438.0  期望 544.0  ✘ 差 -106.0（画布高 614.0≠720：窗口不是 1000:720 比例，属 R7，不是面板算错）
```

**这句才是真话** —— 它说的是"窗口比例不对"，而不是"你把抽屉改坏了"。
