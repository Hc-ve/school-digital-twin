## 1. P0 · 挡住验收（必须修，顺序不要换）

### P0-1 抽屉打开时，别层 UI 没有被隐藏（**根因，先修这条**）

| 项 | 内容 |
|---|---|
| **现象** | ① L2 三页的左轨区域都能看到另一层文字：「未选中 ↑位」「告警与追踪 (4) · 共 4 条 · 已确认 0 · 未确认 4」；② L1 面板中段也有同样的字；③ L1「实时动态」看起来有 5–6 行（规格 4 行），多出来的行其实是这层文字；④ 它还压在工具行上，造成"溢出"假象 |
| **为什么不是页面** | `TwinPageStack.Push()` 里旧页已经 `SetActive(false)`，所以这些字**不属于页面**，而是**独立对象**（旧告警面板 / 交互提示 / 常驻 HUD 文字），不随抽屉层级隐藏 |
| **期望** | 抽屉打开期间（`TwinUIState.Layer != None`），除抽屉自身与触发钮外，**所有场景层 UI 文字/面板一律隐藏**；关闭抽屉后恢复 |
| **具体做法** | 给这类对象挂统一的可见性开关，在 `TwinDrawer` 开/关时统一 `SetActive`；或把它们收进一个 `Canvas_HUD` 下并随 Layer 切换 alpha |
| **验收** | L2 三分页截图里，左轨区域除 5 个 Tab 外**无任何文字**；L1 截图里不出现「告警与追踪」「未选中」字样；L1 动态列表行数恰为 **4** |

### P0-2 面板整体过透，能看清走廊与角色

| 项 | 内容 |
|---|---|
| **现象** | 四张截图都能透过面板看到走廊墙面、门、甚至角色轮廓；文字对比度明显不足 |
| **期望** | 面板区域近乎不透明：`PanelTop` alpha **0.94** → `PanelBottom` alpha **0.96**（既有 token，不用改值） |
| **排查方向** | ① 抽屉/页面的 `CanvasGroup.alpha` 是否停在 0.5–0.7（页推入动画未归 1）；② 抽屉底是否被别处 `SetAlpha` 改过；③ 是否有额外的半透明遮罩叠在上面 |
| **验收** | 在面板空白处与同位置场景各取一点，亮度差 **≥40/255**；面板内 11px 文字在 100% 缩放下可直接辨认，不需要眯眼 |

### P0-3 设备管理：编号列溢出，压住名称列

| 项 | 内容 |
|---|---|
| **现象** | 编号显示的是 TwinId 全串（`ClassComputer/Heat/Radiator_01`），宽度远超 150，直接盖在名称「0住 暖气」上，两列文字叠在一起 |
| **期望** | 编号列**固定 150**，超长一律截断加 `…`（不得压到名称列）；名称列 x 起点 **162**（150 + 12） |
| **验收** | 任意一行中，编号末字符与名称首字符之间 **≥8px** 空隙；不存在两个字符重叠 |

### P0-4 异常 Top3：编号用 TwinId 而非编号规则

| 项 | 内容 |
|---|---|
| **现象** | 三行分别是 `Class2-1/AC/Unit_01`、`ClassComputer/PC/Room_01`、`ClassDirector/AC/Unit_01`——是原始 TwinId，不是「场景-位置-类型-序号」编号 |
| **期望** | 编号格式 `2F-205-走廊灯-003`（13px 等宽）。P3 编号体系未接入前，**至少显示为「2F-205 / 空调-003」这类可读形式**，不得出现 `/` 分隔的原始 ID |
| **验收** | 三行编号均匹配 `^\dF-\d{3}-.+-?\d{3}$` 或约定的降级格式；**不出现 `/`** |

### P0-5 电力管理：影响面卡下沿越界

| 项 | 内容 |
|---|---|
| **现象** | 影响面卡贴着面板底，下沿几乎压到工具行分隔线，第 3 行说明文字离分隔线不足 16px |
| **期望** | 卡 `y=428`、高 `80` → 下沿 **508**（页面坐标），距内容底 544 留 **36** |
| **排查方向** | 树占位 360 是否被撑大（树内容 600 > 360 时**必须内部滚动**，不能把下方元素推下去） |
| **验收** | 卡下沿与工具行分隔线间距 **≥16px**；树区高度恒为 360，不随节点数变化 |

## 2. P1 · 明显别扭（影响观感，进 P29-5 前修完）

### P1-1 告警卡：顶部红线位置错、且没有渐变

| 项 | 内容 |
|---|---|
| **现象** | ① 红线画在了**卡片上边缘之外**（落在两张卡之间的缝里），左右还超出卡片；② 是一条**纯红实线**，右端没有变淡 |
| **期望** | 红线 v 在卡内顶部：`x=12 → W−12`、`y=0 → 2`；颜色 **左端 `#E63939` 100% → 右端 0%** 横向线性渐变 |
| **验收** | 红线完全落在卡片描边以内；右端取样 alpha **≤8%**；左端 Δ 相对卡底 **≥40** |

### P1-2 三套状态词混用（告警 / 警告 / 离线）

| 项 | 内容 |
|---|---|
| **现象** | KPI 卡写「**告警** 4」，同页楼层健康条写「正常 49 / **警告** 4 / **离线** 0」，异常 Top3 标签又写「**告警**」 |
| **期望** | 全项目只用一套状态词：**正常 / 警告 / 告警 / 离线**，且颜色固定：正常绿 `#33CC59`、警告橙 `#FF9E26`、告警红 `#E63939`、离线灰 `#47474D` |
| **关键判定** | 同一批 4 台设备，KPI 叫「告警」就必须在健康条里显示为**红色段**；若健康条显示橙色段，则 KPI 应改叫「警告」。**二者只能有一个名字** |
| **验收** | 同屏出现"告警"字样的地方语义一致（红=告警、橙=警告）；健康条三段之和 = KPI 设备总数（53） |

### P1-3 异常 Top3 状态标签写成「告警」，应为「进行中」

| 项 | 内容 |
|---|---|
| **现象** | 三行右侧标签都是「告警」（橙色） |
| **期望** | 标签承载**处理状态**：`进行中` / `已确认` / `已恢复`；严重度由左侧 3px 色条承载，文字不重复写"严重/警告/告警" |
| **验收** | 三行标签均为「进行中」，且**不出现**「告警」二字作状态 |

### P1-4 设备管理：表头与首行重叠

| 项 | 内容 |
|---|---|
| **现象** | 表头「编号 / 名称 / 位置 / 状态」压在列表第一行（ClassComputer…）上 |
| **期望** | 表头 `y=134..154`，首行 `y=158` 起——表头底与首行顶之间 **4px** |
| **验收** | 表头文字与首行文字**不重叠**，中间可见 4px 空隙 |

### P1-5 电力树：行距过大、层级缩进看不出

| 项 | 内容 |
|---|---|
| **现象** | 12 个节点占满整个树区，行距约 38–40；1F/2F 与其下房间的左右缩进差不明显，看起来是一列平铺 |
| **期望** | 楼栋 **36** / 楼层 **32** / 房间 **28**；每级缩进 **16**；树区固定 360 高，超出**内部滚动**（滚动条宽 4，`#FFFFFF`@0.08） |
| **验收** | 三层文字左边缘各差 16px；树区可见行数 ≥8；节点数增加时只出现滚动条，不改变下方影响面卡位置 |

### P1-6 数据监测：模块说明第二行被 KPI 卡遮住

| 项 | 内容 |
|---|---|
| **现象** | 说明「…（用电量 / 功率 / 温度…）」第二行压在 KPI 卡上边缘 |
| **期望** | 说明区 `y=34..52`，**硬限 2 行**（11px×2），超出截断加 `…`；KPI 从 `y=60` 起 |
| **验收** | 说明文字与 KPI 卡之间 **≥8px**，无覆盖 |
