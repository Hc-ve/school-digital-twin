## 一、先回答"为什么点选老是指向 SchoolBuilding 和 Corridor"

**不是你操作错了，是那块黑天花板本来就属于 `Corridor` 这个对象。**

| 项 | 实测值 |
|---|---|
| 路径 | `SchoolScene/Exterior/SchoolBuilding/Corridor` |
| Renderer 数量 | **1 个**（MeshRenderer） |
| 包围盒 | **52.36 × 3.56 × 24.05 m** |
| 材质槽 | **13 个**（ConcreteWall6d / 6e / 6g / Wood3 / ConcreteStucco02a / FloorLinoleum4a / TileWhite02 / ConcreteStucco01a / ConcreteStucco02d / FloorLinoleum4b / ConcreteStucco02a ×2 / TileArmstrong01_01） |
| lightmapIndex | **4**（仍在走烘焙，未修） |

走廊的天花板、两侧墙、地面、装饰线**全部是这一个 mesh 的不同材质槽**。Unity 的点选只能选到 Renderer 级，所以你点天花板、点墙、点地面，选中的都是同一个 `Corridor`——这不是"选不中"，是**没有第二个对象可选**。

**结论：这里不存在"几何缺失"，不需要补 Plane。** 断点《成果报告》§4 判定的两处缺口，实测都是"几何在、但渲染成纯黑"。

## 五、建议

**不要加 Plane。** 三个理由：

1. 几何本来就存在，加 Plane 等于在一个已经有面位置再叠一个面 → z-fighting 或双份厚度。
2. 走廊天花板是 `Corridor` mesh 的一部分，加 Plane 也盖不住整条走廊（52m 长）。
3. 正确修法就是断点已经验证过的那一条：把这 3 条路径加进 `P30FixCeilingLightmap` 的 `autoPaths` 列表（他在报告里写了"路径可在 Inspector 的 autoPaths 覆盖，改路径不用改代码"）。**这是数据改动，不是代码改动，也不用重烘。**
