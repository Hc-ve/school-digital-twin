## 二、受限根因（工具链，非场景/代码质量问题）

- 总控抽屉触发钮 `TwinTriggerButton`（右上 48×48「控」）：外部合成鼠标移动可触发 `OnPointerEnter`（边框 hover 高亮），但 `OnPointerClick` 未派发 `Toggle()`；连点三次 + 短距拖拽等价按下-松开，抽屉均不开。
- 抽屉内电力树（`TwinSystemPage`）、设备详情卡开关（`TwinControlRow`）同属 UGUI Button，走同一 EventSystem click 路径，预计同样受限。
- 场景 3D 拾取走 `Input.GetMouseButtonDown` + Physics.Raycast，与 UGUI click 是两条路径；但拾取后操作设备仍要回到 UGUI 按钮，绕不开。
- 编辑器 Console 只有日志过滤框，没有可执行 C# 静态方法的命令行入口；`SetEnabled(false)` 无法从外部注入触发。

### 6.3 关灯联动（第 2 项）—— 未验成，F2 选型 bug
- 按 F2 失败，Console：`[IndoorFill][调试] 教室灯键失败：命令中心未挂载`。
- **根因（已定位，代码层）**：调试方法 `IndoorFillLight.cs:800` 取的是 `TwinCommandCenter.Instance`；而命令中心在场景里**不预挂**，要靠公开静态 `Ensure()`（`TwinCommandCenter.cs:95`：Instance null 时在 TwinRuntime 上 AddComponent 自建）。没开过 UI 设备面板时 `Instance` 仍为 null，调试键提前 return。
- 业务对照：UI 入口 `TwinControlRow.cs:197`、`TwinInteractPrompt.cs:302`、`TwinPcMenuDriver.cs:455` 都用 `Ensure()`；Presenter/FullLayer 读 `.Instance` 是在命令中心已被 UI 自举之后。
- **修法**：调试键把 `TwinCommandCenter center = TwinCommandCenter.Instance;` 改为 `TwinCommandCenter.Ensure();`，与 UI 入口一致。修后还需复核 twinId `Class2-1/Light/Main_01` 在 Registry 命中、TrySend 不被 reject。
