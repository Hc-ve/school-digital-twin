## 零、一句话

> **柱面上段死黑不是"不够亮"，是"几何上照不到"——灯在它下方，锥轴朝下，竖面在锥外。**
> 直觉去加灯/提强度/扩锥角全是无效尝试；正解是**换光的形状**（Spot→Point），零加灯。

这条坑的价值在于它给出一个可复用的判据：

> **剪影类问题的第一问不是"亮度多少"，而是"面法线与光源锥轴的夹角是否超过半角"。**

---

## 一、现象

主理人发来一张餐厅仰视图，只框了两个部位、无文字：
- 天花板**横梁**（水平）呈死黑剪影
- 方**柱**（竖直）上段呈死黑剪影

周围墙面、地面、梁底均正常。

---

## 二、根因：三层照明同时缺席竖面上段

柱面上段 y=2.45~3.34，灯管 y=2.21 —— **面在灯的上方**。逐层核算：

| 光源层 | 参数 | 对柱面为什么贡献为 0 |
|---|---|---|
| Fill_Kitchen_04（锥体补光） | 距柱面 2.0m、`cos(N,L)=0.997`（照度条件极好） | 灯→点方向与锥轴 `forward=(0,-1,0)` 夹角 **101.5° > 半角 75°**，恒在锥外 |
| Wash（洗顶灯） | 朝上 Spot、半角 75° | 同样够不到竖直面 |
| Base（全向底光） | 仅 2 盏，z=18.5 / 26.2 | 柱面在 z=28.50 朝 +z（背对 Base）⇒ `cos<0`，数学贡献为 0 |

三者叠加 = 该面**收到 0 光**。

### 关键实证：A/B 逐层分离

| 面 | 改前 | 改后 | 判读 |
|---|---|---|---|
| 梁底 | 0.105 | 0.549 | 正常受光 |
| 墙面 | 0.072 | 0.332 | 正常受光 |
| **柱面** | **0.037** | **0.075** | 增量仅 0.038 —— 黑的是**法线水平的竖面**，不是梁底 |

### 已排除的三个伪解法（都试过、都无效）

| 尝试 | 结果 | 为什么无效 |
|---|---|---|
| Base 抬高 1.5→3.2 | **更暗** | 离得更远，衰减更大 |
| `pixelLightCount` 48→128 | 柱面纹丝不动（0.075/0.068/0.059） | **不是逐像素名额竞争** |
| Fill 锥角 150→178 | 仅到 0.096，仍近黑 | 锥轴向下，扩锥角救不了上方的面 |
| 加 7 盏全向灯 | 可到 0.19 | 能解决但撞 FPS 红线，**否决** |

> 注：`pixelLightCount` 那条是重要排除——"画面暗"的第一反应常是名额不够，但这次数值随名额变化在噪声范围内，证明方向错。

## 三、修法：只换形状，零加灯

新增白名单 `WashOmniZones = { "Kitchen" }`：
- 名单内分区的洗顶灯由「朝上 Spot 150°」改为**全向 Point**
- 强度由 `WashIntensityBig(1.8)` 降到 `WashOmniIntensityBig(0.9375)` 做能量补偿
- **盏数 / 位置 / 父子关系 / 驱动链路 / range 全部不变**

扩范围只需往白名单加名字，可按分区灰度。灯数 404/83/36/86 逐位不变。

## 四、坑中坑：0.75 首版翻车的算术口径

首版常量填 `0.75`，实测柱面只到 0.151（预期 0.20）。原因：

```
扫参得到的 0.75 是【生效值】
常量在 Apply() 里还要再乘 P41c 的 NightDim 0.80
⇒ 实际生效 = 0.75 × 0.80 = 0.60
⇒ 正确常量 = 目标生效值 ÷ NightDimFactor = 0.75 / 0.8 = 0.9375
```

**裁决：保留 0.9375**。口径统一为「常量 = 目标生效值 ÷ NightDimFactor」，
不在 Apply() 里对 omni 分区跳过 NightDim —— 那会让"降灯"语义分裂成两套。

> 这是典型的"参数口径不一致"坑：扫参界面的值和代码里的值差一层乘算。以后任何参数是"扫出来的"，落地前必须确认它在调用链上还乘了什么。

## 五、FPS 口径：组间漂移大于 A/B 差，不许声称提升

| 采样 | 中位帧时 |
|---|---|
| P42 Point（当轮） | 153.06 ms |
| 改前 Spot | 155.74 ms |
| **同状态复测（还原 Point）** | **160.43 ms** |

A/B 差 2.7ms，**组间漂移 7.4ms > A/B 差** ⇒ 判定「无可测性能差异」。
裁决：不声称有提升。`cam.Render` 单次绝对值不可比，严格结论需 Profiler 采样或真机帧率。

> 教训：任何"A 比 B 快 X%"的结论，必须做**同状态复测**确认漂移量级。一次 A/B 对比不足以支撑性能结论。

## 八、可复用清单（下次遇到"竖面死黑"）

1. 先算**面法线 vs 光源锥轴夹角**，不要先看亮度数值 —— `cos(N,L)=0.997` 却照不到，说明问题在锥角剔除
2. 做**逐面 A/B**（梁底/墙面/柱面分开采样），确认黑的是哪一类法线
3. 排除清单：Base 高度、pixelLightCount、锥角扩展 —— 三项都无效就别再扫
4. 零加灯方案：Spot→Point + 能量补偿，按分区白名单灰度
5. 参数是扫出来的 → 落地前核对调用链上的乘算
6. 性能结论 → 必须同状态复测，漂移 > A/B 差就不下结论
