## 0. 为什么改回 20/60/20（先认个错）

v1 我否决了 20/60/20，理由是"两侧各 200 放不下 121 宽的 KPI 卡"。**这个理由是错的**：

- 我把"三张 KPI 卡横排"当成了硬约束。但行业大屏的左右栏**本来就是竖排卡片**——200 宽栏里放一张 168×88 的卡，竖着排三张，这才是标准做法。
- 我算的"中间只剩 600"其实**比 v1 方案的 584 更宽**。等于我用更窄的中区去换一个并不存在的优势。

所以 v2 全部推倒重来，按行业规范来：**左 20% + 中 60% + 右 20%，头 80 / 底 60**。

### 案例 1 · 通用大屏布局规范（CSDN《数据可视化大屏布局：从逻辑到落地》）

| **实测数值** | 头 **80px**、底 **60px**、左右各 **20%**、模块 gap **20px**、容器 padding 20×30、圆角 **8px**、边框 1px `#1f2937` |

|---|---|

| 项 | 内容 |

| **可照搬** | **数据模块并列、指标卡与图表混排**——本项目左右栏就是这种密度 |
| **不能照搬** | 12 类数据源本项目只有 95 指标 / 53 台设备；拼接屏横向空间也没有 |

### 案例 5 · 某园区沉浸式落地（游戏级引擎）

| 项 | 内容 |
|---|---|
| **布局骨架** | 三维 80%+，UI 极简（只留标题、少量指标、操作入口） |
| **可照搬** | **"UI 越少越高级"**——左右栏只放必要卡片，不要塞满 |
| **不能照搬** | 依赖高精模型与实时光照 |

### 1.6 结论：照搬 20/60/20，只做三处本地化

| 照搬 | 本地化（因为 1000×720 + 零图片 + UGUI） |
|---|---|
| 左 20% / 中 60% / 右 20% | 侧栏 384→**200**；卡宽 168（栏内 −32 内边距） |
| 头 80 / 底 60 | 原样用 **80 / 60**（不再自创 72） |
| gap 20 / 圆角 8 | 卡片间距 **8**（1000 宽下 20 太散）、圆角沿用 R12 |
| 左右栏竖排卡片 | KPI 三卡**竖排**，不横排 |
| 三维居中为主视觉 | 3D **600×580**，相机不动 |

## 2. 骨架：一屏三段 + 上下两条带

```
┌──────────────────────────────────────────────────────┐
│ 顶带 80：标题 · 副标 · 摘要 · 最大化 / 关闭            │
├────────┬──────────────────────────────┬──────────────┤
│ 左栏    │                              │ 右栏          │
│ 200    │        3D 600×580            │ 200          │
│        │        （相机不动）           │ 上下文面板     │
│ KPI×3  │                              │ 告警 / 详情    │
│ 入口    │                              │              │
│ 动态×3  │                              │              │
├────────┴──────────────────────────────┴──────────────┤
│ 底带 60：数据源 · 录制 · 帮助 · 设置 ······ 时间/版本   │
└──────────────────────────────────────────────────────┘
```

**校验**
```
横向：200 + 600 + 200 = 1000 ✔
纵向：80 + 580 + 60  = 720  ✔
3D 可见：600×580 = 348,000 px² = 全屏 48.3%
```

> 与 v1 对比：3D 宽 584 → **600（+16）**，且左右都有数据栏，视觉上更"大屏"。

## 4. 两条硬约束

### 4.1 坐标系不变
全屏态在 **1000×720 逻辑坐标**内重排，不引入第二套坐标系、不做 scale 变换。全屏 = 把面板从"右侧 420"改成"左右两栏 + 中间 3D"，**是同一坐标系里的重新摆放**。

### 4.2 3D 不裁窄
**L1 全屏时 3D 可见尺寸 ≥ 600×580**（x 200–800，y 80–660）。禁止用相机 viewport 裁切给面板让位——数据栏是浮在上面的实底卡片，3D 渲染始终全屏。

## 5. 断点 8 个问题的答案（v2）

| # | 问题 | 答案 |
|---|---|---|
| ① | 内容宽度策略 | **左 20% + 中 60% + 右 20%**（200/600/200），行业主流三栏；不用居中定宽、不用拉伸铺满 |
| ② | L1 KPI 3 列还是 4~5 列 | **都不是：竖排 3 张 168×88**，栏内单列。200 宽放不下两列 |
| ③ | L2 左轨是否变宽、右区怎么分 | 左轨 **168→200**；右区 440 → **中栏 600 + 右栏 200** |
| ④ | 工具行四项 | 底带 60 通栏，四项 **x=20/116/212/308 左对齐**；右侧放时间/版本（右对齐 980） |
| ⑤ | 头部对齐基准 | **内容左缘 = 20**（不是屏幕边缘 0，也不是栏内 16）；右基准 **980** |
| ⑥ | 列表列宽是否变 | L1 动态行宽 **168**（3 行），不补列；L2 台账主栏 600 → **6 列可放**：编号 150 / 名称 150 / 位置 90 / 类型 72 / 状态 56 / 开关 44（合计 562 + 5×6 = 592 ≤ 600 ✔） |
| ⑦ | 小地图、详情卡 | 小地图**保留在 3D 左上**（x 200–320，y 96–216）；详情卡**改为右栏切换**（点设备 → 右栏从告警切到"设备详情紧凑版"），不再用 470 浮卡 |
| ⑧ | 大屏感元素 | **只加三样**：顶带主色分隔线、左右栏卡片序号、底带时间/版本。**不加**地图铺底、粒子、流光、毛玻璃 |

### 5.1 关于详情卡（这条最容易被做错）

全屏三栏下，3D 只有 600 宽。若还弹 470 的详情卡，3D 只剩 130 —— 等于毁掉卖点。

**解法：全屏态详情卡 = 右栏内容切换。**

| 状态 | 右栏内容 |
|---|---|
| 默认（未选设备） | 告警列表 3 条 + 设备类型分布 |
| 点 3D 设备 / 点列表行 | **切换为「设备详情」**：编号（全码 11 等宽，2 行折行）+ 状态胶囊 + 4 项关键指标（竖排 48 高）+ 开关按钮 + 「返回告警」文字按钮 |
| 关闭选中 | 切回告警列表 |

窄态仍用 470 浮卡（已通过，不改）。**这是两态唯一的形态差异，要在验收时分开看。**

## 6. 三项已裁决的落点（不变）

### 6.1 编号
| 位置 | 格式 |
|---|---|
| 列表 | 短码 `2F-205` |
| 异常 Top3 | `2F-205 空调` |
| 详情（窄态浮卡 / 全屏右栏） | 全码 `1号教学楼-2F-205-空调-001` |
| 禁止 | 原始 TwinId（含 `/`） |

### 6.2 量词
- 统一 **「台」**；「个监测点位」**只在 L1 第一张卡**出现一次（9.5px 副行）。

### 6.3 状态词与健康条
- 统一 **「告警」**。
- 健康条按组内最严重级别取色：Alarm 红 `#E63939` / Warning 橙 `#FF9E26` / 仅 Normal 青绿 `#33CC59` / 有离线 灰 `#47474D`；优先级 **离线 ＞ Alarm ＞ Warning ＞ Normal**。
