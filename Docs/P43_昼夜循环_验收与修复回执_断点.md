## 二、验收发现的 4 个缺陷与修复（全部已落地）

### P0 · 密度三档对主雨雪完全失效（修复 1）
- **实测根因（非猜测）**：`RainParticles`/`SnowParticles` 因 P13-D9 刻意**不挂父节点**（世界坐标定位，挂子级会被楼板吃掉发射盒），而 `ApplyParticleDensity` 用 `GetComponentsInChildren` 只够到子级 `RainSplash`。实测切「小」：雨丝 3200 粒/s、4699 粒纹丝不动，仅水花倍率变化。另微测试证实三份速率曲线均为 **Constant 模式**，`rateOverTimeMultiplier` 在该模式下读改不可靠且会被 Apply 重写覆盖——multiplier 方案整体废弃。
- **修法**：`WeatherVisuals` 新增 `SetDensityScale(k)`（复位 lastRain/lastSnow/lastSplashRain 三缓存为 -1 哨兵，强制下一次 Apply 全量重写）+ 三路写入乘 `_densityScale`（默认 1，行为与历史版本一致）；`TimeCycleDirector.ApplyParticleDensity` 改调它。
- **复验实测**：雨 Medium 3200 → Low **1120(=3200×0.35)** → High **6400(=3200×2.0)** → Medium 3200；雪 Low **182(=520×0.35)**；粒子数实时跟降（4714→1647→8995）；跨天气切换（雨→雪）倍率持续生效。

### P1 ·「随机」按钮语义矛盾（修复 2）
- **根因**：旧实现点「随机」= 摇一次骰子 + `SetAuto(false)` 永久退出自动轮换，之后无任何 UI 路径能回随机模式——与主理人"默认处在随机选项、循环中随机天气"诉求相反。
- **修法**：`CommitPendingWeather`：确认「随机」= `SetAuto(true)` 回权重链（`SetAuto(true)` 自带缩短首次轮换计时）；确认具体档才 `SetAuto(false)`。
- **复验实测**（走真实 UI 路径反射调用）：雨天+确认→auto=False ✓；随机+确认→auto=**True** ✓；晴天+确认→False ✓；随机+确认→True ✓。

### P2 · 初始高亮误导（修复 3）
- **根因**：play 后系统实际处于自动随机模式，但天气钮高亮「晴天」（当前档），误导"天气被钉死"。
- **修法**：`RefreshButtons` 增分支：无预览且 `WeatherDirector.Instance.auto` → 高亮「随机」（模式语义优先于当前档）。
- **复验**：auto=true 时钮[0]◉选中其余未选；截图 `P43_fix_verify_random_highlight.png`。

### P2 · 面板冻结基准不同源（修复 4）
- **根因**：`Pause()` 冻结用墙钟 `CurrentHour()`，而 `Resume()` 与表盘都读 `TwinClimate.HourOfDay`——三处两口钟，每次开合面板静默丢最多一帧的游戏时间（掉帧时放大到数游戏分钟，实测表盘 08:03 vs 冻结 08:06）。
- **修法**：`Pause()` 改取 `NormalizeHour(TwinClimate.HourOfDay)`。
- **复验**：面板开着时循环冻结值 = 数据侧时刻 = **0.00000000 差值**（修复前 ≈ 0.002~0.05h）。

## 六、追补（11-17 凌晨 · 主理人 play 反馈：撒播高度太低）

**反馈原话**：雨雪撒播高度只比教学楼高一点点，现实不是这样，要求调高。

**取证**：`EmitHeight = 16f`（WeatherVisuals.cs:25），发射点真实语义 = **室外地面 + 16m**（`UpdateGround` :3912 `emitPos.y = outdoorGroundY + EmitHeight`，:25 旧注释写"相机上方"是过时表述）。教学楼约 15~16m ⇒ 雪恰好从楼顶一线凭空出现，观感属实。

1. `EmitHeight 16 → 60`（教学楼 3.75 倍）。寿命**不用改**：`UpdateRainLifetime`/`UpdateSnowLifetime` 是按实测落距解 `t=√(2h/g)` 的解析式（0.5s 节流重算），落距变大自动跟随——设计初衷就是防"落距变了寿命写死"。

## 八、追补三（11-17 · 主理人三轮反馈：树冠太假先调研 / 雨天楼顶要湿）

**主理人诉求**：① 树冠覆雪太假，**先调研**业界做法与真实形态再动手；② 雨天楼顶没有湿润/水坑效果；③ 雪壳大体认可但有细节缺陷。

### 调研（按 §6.10 调研前置）
- **业界实现**（3+ 案例）：主流是「**法线朝上遮罩 + 积雪量**的材质混合」（One Wheel Studio 低模雪 shader / Snow Covered Shader / Kronnect URP 指南——后者专门讲了树叶 forward-pass 的处理），另一路是屏幕空间后处理积雪（The Knights of U）。**映射本项目**：材质混合路需要对树叶材质插手，而地形树原型材质是**共享资产**（Hidden/Nature/Tree Creator Bark Optimized），运行时改会污染会话（B1 同型病），Terrain 批渲染也吃不到 renderer 级 MPB → **不可行**；屏幕空间路对 alpha-cutout 树叶边缘效果差且要动后处理 → 不取。
- **真实形态**（照片参考）：雪只挂枝/叶**上表面**；呈**不连续簇状**、叶簇间露暗底；越靠外缘越薄；均匀白帽=假。
- **结论**：走几何路，但必须"簇状+贴体"，弃均匀帽。

### 两版证伪（都发生在本轮，完整记录防走回头路）
1. **v2 半球帽**（初版）：均匀白盘悬在树冠上 → 主理人评"太假"（根因：均匀覆盖+不贴体）。
2. **v2.5 贴体雪层**（复制原型叶卡三角形沿法线外扩）：本素材树叶不是细碎叶面，而是 **2~5m 的大 alpha 叶卡**——按面积取最大的雪层直接变成**巨片白色平板穿过树冠**，当场证伪。同型教训在雪壳系统又踩一次：v2 给独立树（Tree1/2/3(Clone)）生成的"列顶壳"也是整张大叶卡 → 巨片白板。**两处都已排除**（雪壳筛选 + 烘焙工具均排除 `Hidden/Nature/Tree*`）。
3. **v2.6 采样区教训**：树冠区写成"从低位起全收"→ 面积最大的叶卡集中在**冠底**，前 N 名全是低位卡，冠顶反而无雪（俯拍实证）→ 改为**只取树冠顶部区段**（topY ≥ 树高×(1−K)）。
4. **v2.7 长条带教训**：采样噪声频率 0.9 太低（0.3m 间距下相邻点噪声几乎相同）→ 雪斑连成沿叶卡方向的**长条白带** → 噪声频率提到 3.4（补丁级）+ 保留率 0.8→0.6 + 中心抖动 ±0.09。

## 七、追补二（11-17 · 主理人二轮反馈：高度再抬 + 楼顶/树冠/灯顶没雪）

### ① 撒播高度改为「相机自适应」
- 动因：主理人航拍（自由相机 100~150m 高）时固定 60m 的发射面就是一顶"雪天花板"。
- 修法：发射 Y = **max(室外地面+60, 相机+40)**，封顶 地面+250（给寿命解析式与粒子缓冲可算边界）。
- 连带：雪寿命 Clamp 上限 30→40s（250m 落距 t≈37.4s）；雨/雪 maxParticles 24000/22000→**45000/45000**（250m 满载 High 档 ≈39k，防静默截断）。

### ② 雪覆盖 v2（屋顶雪壳事故 D11/F20 的正式重做）
- **为什么运行时扫描不行（新取证）**：场景开了**静态批处理**，建筑运行时网格全是 "Combined Mesh (root: scene)"——**758 个、CPU 不可读**，运行时扫描永远只够到 55 个未合批小网格（树/门廊），楼顶缺失是**结构性**的。
- **架构**：**编辑器烘焙 + 运行时直接用产物**。新工具 `SchoolTwin/雪壳/① 烘焙屋顶雪壳`（`RoofSnowBakeTool.cs`）：编辑模式无批处理、原始网格+真实 Transform、编辑器读顶点不受 isReadable 限制 → 三层筛选后把世界坐标雪壳烘焙成 prefab（`Assets/_Project/Weather/RoofSnow/Resources/RoofSnowBake.prefab`，62 片 .asset 分片）。场景改动后重跑一次即可。运行时 SnowOnRoofs 路径 A 直接实例化（零扫描），路径 B 运行时扫描兜底。
- **v2 判据（按分册 §八，堵死 v1 四路连带）**：
  ① 判"屋顶"= 三层过滤：粗筛（法线朝上≥0.55/面积≥0.35㎡/世界Y≥3m）→ **逐列最高朝上面**（1m XZ 栅格，只有列顶才收——楼板/吊顶上方恒有更高列顶面，天然出局；共享大网格里的矮楼顶也正确入选）→ 相对高度≥0.5 兜底。**不再用世界绝对高度**（v1 真根因）。
  ② 一楼一壳（每来源一片），不再是全场景单块。
  ③ renderQueue 2996（v1 的 2997 是连带之一；屏幕 Geometry 2000 且室内面已出局）。
  ④ **壳永不带 Collider**——SampleGroundHeight/脚印走物理射线，无碰撞体天然免疫（v1 角色浮空通路切断）。
  ⑤ `IndoorByRendererRoof` 建表按雪壳着色器名/物体名双排除（室内判定翻转通路切断）。
- **树冠**：地形树原型材质是**共享资产**，改 _Color 会污染会话（B1 同型病）→ 走独立几何：`SnowOnTrees` 加**树冠雪帽**（扁半球，树高×0.86 处，半径=树冠包围盒×0.75，与树根雪堆同材质同雪量，单独 mesh 一 draw call）。场景里的独立树（Tree1/2/3 等）由雪壳 v2 的列顶判据自然覆盖（树冠顶面就是列顶）。
