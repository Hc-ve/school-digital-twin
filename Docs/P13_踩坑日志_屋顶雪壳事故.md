## 三、真根因：`minRoofY` 是世界绝对高度

`SnowOnRoofs` 的筛选判据是三条：

```csharp
if (minY < minRoofY) continue;          // 位置门槛
if (area < minTriArea) continue;        // 面积门槛
if (wn.y < minUpNormal) continue;       // 朝向门槛
```

日志：

```
[P13][屋顶积雪] 雪壳已生成：4067 个三角形 / 12201 个顶点
                （扫描 56 个网格，71718 个三角形）
```

**4067 个三角形 = 一个覆盖整个校园的巨型网格。**

问题出在 `minRoofY = 3.2f` 是**世界绝对高度**，不是"相对该建筑的高度"：

| 被误判为"屋顶"的几何 | 世界 Y | 为什么通过 |
|---|---|---|
| 机房 1F 天花板 | ≈3.0m | 部分顶点 >3.2 → 通过 |
| 二层楼板 | ≈4~7m | 全部通过 |
| 走廊吊顶 | ≈3m | 通过 |
| 楼梯平台 | 逐级升高 | 全部通过 |
| 看台顶面 | 3~8m | 全部通过 |
| 广场铺装 | ≈0m | 被正确拦下 |
| 球场地面 | ≈0m | 被正确拦下 |

于是雪壳里混进了大量**室内水平面**。主理人机房截图上那块
「从天花板斜插下来、边缘呈三角形拼接的黑色几何体」，就是它。

## 四、四路连带的完整因果链

一条根因，四条完全不同的故障表现。**这就是为什么它难查**：
四个现象看起来毫无关系，容易被当成四个独立 bug 分别去修。

### ① 机房幕布发黑

```csharp
shellMat.renderQueue = 2997;   // 我参照树根雪堆写的
```

`2997` 排在近场雪盘（2996）、远场（2995）、以及**幕布与所有屏幕**之上。
雪壳是半透明大面，一旦盖在幕布前面，幕布就被压黑。

更糟的是雪壳里有大量**室内几何**，等于在机房里直接插了一块黑板。

### ② 角色浮空

`SampleGroundHeight` 的判据是「取最接近 `refY` 的朝上面」：

```csharp
const float MinUpNormal = 0.6f;   // 朝上才算
// 策略：min(|y - refY|) 而不是 max(y)
```

雪壳是朝上的大面，正好满足 `MinUpNormal`，且位置就在玩家头顶上方。
射线从 `eyeY + 2` 往下打，**先撞到雪壳**（或雪壳成为"最接近 refY 的朝上面"），
于是地面采样点从"地面"变成了"雪壳顶"。

→ 角色脚下雪面高度被算成屋顶高度 → `UpdatePlayerOnSnow` 把角色抬到空中。

### ③ 脚印消失

`UpdateFootprints` 与 ② 共用同一份 `playerSnowAmount` 与同一套地面采样。
采样点错了，脚印的世界坐标就全错了——画在看不见的地方。

### ④ 屋顶反而仍无雪

雪壳是**一个 mesh**，4067 个三角形混在一起：

- 有真的屋顶面，但很多建筑是双面材质，`_Cull=2`（Back）把一半剔掉
- 有大量室内面，把整体 `bounds` 撑得极大
- `_MaskOff=1` 让覆盖率恒 1，但几何本身就糊成一团

**四个现象里最难接受的是：这个功能连自己的目标都没达成。**

## 五、为什么"调参数"救不了

我评估过三条修补路线，全部否掉：

| 方案 | 为什么不行 |
|---|---|
| 抬高 `minRoofY` 到 12m | 连带漏掉 1~2 层楼的屋顶（教室楼本身才 12m、机房在 1F） |
| 按建筑根节点分组 | 需要先有可信的建筑清单；本工程 1393 个 PrefabInstance、建筑网格全在 prefab 里，没有现成清单 |
| 排除室内（用 `indoor` 判定） | 顺序矛盾：`indoor` 判定本身依赖场景几何，会形成循环依赖 |

> **教训 ②：当"调参数"和"改架构"都不可行时，正确的动作是停用，不是硬凑。**
> 答辩前一天，一个达不成目标还破坏四处的功能，收益是负的。

## 六、第二个坑：改共用着色器 = 改全局行为

我为雪壳给 `SnowGround.shader` 加了两个属性：

```hlsl
_MaskOff  ("Ignore Snow Mask (roof shell)", Range(0, 1)) = 0
_Cull     ("Cull Mode", Float) = 0
```

虽然是**纯加法**（默认值 = 原行为），但这里暴露了一个结构性风险：

> `CampusUI/SnowGround` 是**四份几何共用一个着色器**：
> 近场雪盘、远场雪盘、树根雪堆、雪壳。
> 为一个使用者改着色器，等于同时改另外三个的渲染语义。

本次能全身而退，是因为两个默认值都选了"保持原行为"（`_MaskOff=0`、`_Cull=0`）。
如果当时图省事把 `_Cull` 默认值写成 2，地面雪盘会整体变单面，
从上方俯视时整片地面消失——又是一个查半天的 bug。

**已用判据锁死（P13-72）：`_Cull` 默认值必须是 0。**

## 八、给下一次重做的判据（写在这里，别重新想）

真问题不是"怎么复制朝上面"，而是**"怎么知道哪块面属于屋顶"**。三条可行路线：

| 路线 | 思路 | 已知风险 |
|---|---|---|
| **按建筑根节点分组** | 先收集 `SchoolBuilding*` / `BuildingBig02*` 等 prefab 实例的根，只对子树建雪壳 | 需要一份可信的建筑清单；部分建筑可能共用父节点 |
| **逐点向上探测** | 在建筑投影范围内撒网格点，每点向上打射线取最近命中面，只收那一小片 | 坡屋顶会出锯齿；点数与精度要权衡 |
| **法线+高度双层过滤** | 要求 `minY` 相对该网格自身 `bounds.min.y` 高出 ≥60%，而不是世界绝对高度 | 单层大跨建筑（篮球馆）会整片被漏掉 |

**共同前提**：绝不能再用"世界绝对高度"当判据，也绝不能把结果塞进一个
覆盖全场景的 mesh。必须按建筑分成多个小 mesh，且 `renderQueue` 不得高于屏幕。

**最有价值的一步是「找共用点」**：四个现象分别属于

> **教训 ③：多个不相关现象同时出现时，不要分别排查，
> 先找它们的共用点。** 一个 bug 引起四个现象，比四个 bug 同时发生更可能。
