`Assets/_Project/Scripts/Present/AcAirflowFeedback.cs`（新建，**1094 行**）

出风口每帧发射**沿吹风方向拉伸的丝状半透明粒子**，靠 `Stretch` + `Noise` + 高斯长尾贴图三者叠加成雾。

| 参数 | 值 | 依据 |
|---|---|---|
| `startLifetime` | 2.2 ~ 3.4 s | 要飘够远才看得见 |
| `startSpeed` | 0.75 ~ 1.35 | Stretch 长度 ∝ 速度 |
| `startSize` | 0.10 ~ 0.22 | 拉伸会放大 2~3 倍，基础值必须小 |
| `startColor` | (0.86, 0.94, 1.0, **0.26**) | 冷白偏青，纯白像雪 |
| `gravityModifier` | **+0.012** | 正数 = 下沉（冷气）；负数是烟 |
| `maxParticles` | 110 | 单根丝细，靠数量交叠成雾 |
| `rateOverTime` | 24 | 同上 |
| `shape.angle` | 13° | 太窄会挤成一根管子像激光 |
| `shape.radius` | 0.42 | 空调长边 1.05m 的一半 |
| `shape.scale` | **(1, 0.28, 1)** | 压成沿墙窄缝，不是圆盘 |
| `shape.rotation` | **zero** | Cone 默认沿本地 +Z，方向由 Transform 决定 |
| `renderMode` | `Stretch` | 圆点阵永远不像气 |
| `lengthScale` / `velocityScale` | 2.3 / 0.35 | 基础长宽比 + 速度拉伸 |
| `alignment` | `View` | 始终对着相机拉伸 |
| 混合 | `SrcAlpha / OneMinusSrcAlpha` | 亮背景下 Additive 无效 |
| 贴图 | 128×128 高斯 `exp(-4.2r²)` | 长尾才有两端渐隐 |

### 1.2 程序化嗡鸣（听觉通道）

同一文件内 `BuildHumClip()`，**零素材**（代码合成，不读 wav，不碰 `Resources.Load`）。

```
风噪（带通 180~2400Hz 白噪声）  55%
  +
谐波（50 / 100 / 150 Hz）      45%   ← 只作底噪基底
  ↓
4.00 s 循环，直接截断，不交叉淡化
  ↓
AudioSource: spatialBlend 0.45 / Linear / min 3 / max 30 / 满音量 0.18
```

| 关键量 | 值 | 理由 |
|---|---|---|
| 循环长度 | **4.00 s** | 50/100/150Hz 在 4s 内恰好 200/400/600 整周期；2s 有「洗衣机」重复感 |
| 循环接缝 | **直接截断** | 实测跳变 0.1059 = 噪声自身相邻差的 **76.9 百分位**，被完全掩蔽 |
| 风噪下限 | 180 Hz | 笔记本喇叭低频死区在 150~250Hz，再低等于白给 |
| 风噪上限 | 2400 Hz | 再高变成「嘶嘶」的电视雪花声 |
| 满音量 | **0.18** | 0.16 听不见 → 0.55 偏吵 → 0.18 为 0.55 的 1/3 |
| 起播策略 | **只 Play 一次，永不 Pause** | Pause 释放混音器通道 + `time` 不归零导致起始相位跳变 |

> 编号 `B` 开头。每条都实际踩过，都给出**原因**与**解决方法**。

### 2.1 视觉形态（7 条）

| # | 现象 | 原因 | 解决 |
|---|---|---|---|
| **B01** | 每个粒子是一个**白色硬边方块**，像纸屑 | `BuildParticleMaterial()` 只做了 `Shader.Find`，**没给 `_MainTex`**。`Particles/Standard Unlit` 的 `_MainTex` 默认是白图 | 代码生成柔边贴图写入 `_MainTex`（零素材红线不破）。**`Shader.Find` 成功 ≠ 材质可用** |
| **B02** | 方块没了，但变成一堆散开的小白点，像加湿器 | **范式错**：用的是 billboard（各向同性圆点）。参考图里是沿吹风方向拉长的光丝交叠成雾 | 换范式：`renderMode = Stretch` + `lengthScale 2.3` + `velocityScale 0.35`。**连调两轮参数都救不回来，因为参数改不了范式** |
| **B03** | 粒子**往上飘**，像烟或热气 | `gravityModifier = -0.015f`。负值是向上，冷气是向下 | 改 `+0.012f`。叠在「本来就是点阵」上时，整幅画面变成「白点往上飘」，与空调物理完全相反 |
| **B04** | 白墙上多了一块**更白的糊**，丝状结构全消失 | `_DstBlend = One`（Additive 加色混合）。理由写的是「气流是发光雾气」，但**该理由只在深色背景成立**。教室是白墙 + 白天光照，白 + 白 = 白 | 改 `SrcAlpha / OneMinusSrcAlpha`（Alpha Blend）。**参数的正确性依赖环境，不依赖它看起来多合理** |
| **B05** | 拉长后变成**边缘清晰的实心棒**，像拉丝的糖 | 贴图是 `(1 - r²)²`，中心实、到 r=1 才归零。圆点形态下没问题，Stretch 后中段（r≈0.5~0.8）衰减不够快 | 改高斯 `exp(-4.2r²)`：r=0→1.000 / 0.35→0.593 / 0.55→0.281 / 0.75→0.094 / 1→0.015(裁 0)。分辨率 64→128（拉长后 64px 横向插值有可见锯齿） |
| **B06** | 粒子**从出风口垂直往下撒**，根本没朝房间吹 | `shape.rotation = (90,0,0)`，注释写的是「锥轴朝本地 +Z」——**这句注释本身就是错的**。Cone **默认就沿本地 +Z**，`shape.rotation` 是附加旋转；绕 X 转 90° 把锥轴从 `+Z` 转到 **`-Y`（世界垂直向下）** | `shape.rotation = Vector3.zero`。方向由 `root.transform.rotation = LookRotation(blowDir, up)` 决定。**这是全包最隐蔽的一个 bug，伪装了六轮** |
| **B07** | 出风口是一个**直径 84cm 的圆盘**，像加湿器喷头 | `shape.radius = 0.42` 是半径，实际直径 0.84m。真实壁挂空调出风口是沿机身长边的一条 **3~5cm 窄缝** | `shape.scale = (1f, 0.28f, 1f)` 压成椭圆。注意 `shape.scale` 只影响**发射区形状**，不影响粒子尺寸，这点容易混淆 |

### 2.2 出风口定位（4 条）

| # | 现象 | 原因 | 解决 |
|---|---|---|---|
| **B08** | 推导位置偏离实际出风口 0.056m | 原式 `b.center + blowDir * (halfThin * 0.75f) + up * (-s.y * 0.35f)`，对 `(0.15,0.30,1.05)` 只偏移 0.056m，**1.05m 的长边完全没参与计算** | 法线方向 `thick*0.5+0.02`、高度方向 `height*0.5-0.03`，让两个维度都进公式 |
| **B09** | 同一侧墙的两台空调**朝相反方向吹** | 房间中心取的是 `GameObject.Find(zone).transform.position` —— 那是**根节点 pivot**。FBX 导出的空父节点 pivot 常在门口 / 墙角 / 世界原点 | 取房间内**所有 Renderer 的合并包围盒中心**（几何中心）。这个量不受 pivot 影响，只跟房间实际摆了什么有关 |
| **B10** | 投影接近 0 时方向符号不稳定 | 房间特别窄、或空调恰好在中线上时，`Dot` 结果在 0 附近抖动 | 兜底判据：改用**离墙远近**——壁挂空调必然贴墙，朝**远的那侧**吹 |
| **B11** | 花盆架 `FlowerHolder01b` 被判成空调 | 第一版四条绝对阈值（`horizMax>0.5` / `horizMin<0.50` / `s.y<0.70` / `y∈[1.6,3.4]`）**全被通过，一条区分力都没有** | 补**比例判据**：`长边/厚度 > 3.0`、`长边/高度 > 2.5`。真空调 7.0/3.5，花盆架 2.4/1.3。同时收紧绝对值（厚度 <0.30、高度 <0.45） |

### 2.4 音频（7 条）

| # | 现象 | 原因 | 解决 |
|---|---|---|---|
| **B15** | 完全**没有嗡鸣声** | 音量只有提示音的 **1/6（−15dB）**：「滴」= 波形 0.42 × 音量 0.75 = **0.315**；嗡鸣 = 谐波和 1.13 × 0.30 × `HumMaxVolume` 0.16 = **0.054**。0.16 是照「背景音不该盖过提示音」定的 —— 那句话没错，但**没人算过它到底有多小声** | 先改 0.55（与提示音同量级），主理人试听后裁决「偏吵」→ 最终 0.18。**「低调」和「听不见」之间只隔一个乘法** |
| **B16** | 音量够大了，但听起来像**变压器 / 镇流器**，不像空调 | 只有 50/100/150Hz 三个正弦。真实空调运行声 = **压缩机低频谐波 + 出风宽带湍流噪声**，且**风噪占大头** | 加一层带通白噪声（180~2400Hz），占总音量 **55%**，谐波降到 45% 只作底噪基底 |
| **B17** | 站讲台时**听不见**，走近才有 | 上一版 `spatialBlend=0.75 / min 2 / max 16`。Linear 滚降在 8m 处只剩 50%，再乘 0.75 权重 ≈ **0.31 贡献**。而答辩时人站讲台，5 台空调都在 6~10m 外 —— 正好落在最亏的位置 | `spatialBlend 0.45 / min 3 / max 30`。空调嗡鸣本就是弥漫环境声，不需要精确声像；满 3D 反而像「耳机里有个点」 |
| **B18** | 带通滤出来的**低频不降反升**，40Hz 比通带还响 | 「两个低通相减做带通」：白噪声分别过 `fc=2400` 和 `fc=180` 两个低通，然后 `high - low`。**这个结构在低频不是高通** —— 两个低通在低频都趋近 1，相减趋近 0，但级数越高「趋近」得越慢，差值反而更大 | 改**高通级联 + 低通级联串联**，各 2 级。实测频响：20Hz −38.3dB / 40Hz −26.6dB / 120Hz −10.3dB / 500Hz −1.6dB(通带) / 2kHz −4.8dB / 8kHz −20.9dB |
| **B19** | 给噪声循环做了交叉淡化，反而听到**每次循环「突然变轻」** | 直觉「噪声首尾不连续必须淡化」是错的。交叉淡化让末尾 0.5s 变成两段独立噪声混合 → **方差减半 → 那才是真正可听的变化**。而接缝本身：4s 直接截断的跳变 0.1059 落在噪声自身相邻差的 **76.9 百分位**，被完全掩蔽 | 4s **直接截断**，不做交叉淡化；循环长度同时 2s→4s，消除宽带噪声的重复感。**不要为了解决一个听不见的问题，引入一个听得见的问题** |
| **B20** | 每次开空调起始相位都不同；低配机器上提示音被挤掉 | `Pause()` 两个副作用：① **释放混音器通道**（5 台反复申请/释放会挤掉提示音）② **`time` 不归零**，下次 `Play()` 从该位置继续 | `HumStarted` 标志位：**只 Play 一次，之后永不 Pause**，安静时靠 `volume = 0` 无声播放。代价是 5 条 4s clip 空转（CPU 可忽略），换来零起播延迟 + 相位永远连续。断电是唯一例外：真 `Stop()` + 复位 `HumStarted` |
| **B21** | 音源在断电后**仍无声占用通道** | 断电只把 `volume` 归零，没 `Stop()` | 断电分支真 `Stop()` + `u.HumStarted = false`（判据 P14-33） |

## 三、三次误判（比 bug 更该记）

这三条的共同点不是「代码写错」，而是**我脑子里先有结论，再去找证据**。它们差点把正确的东西改坏。

### 误判一：把「两台空调在 6 米高空」当成 bug（险些误杀两台）

**我怎么想的**：日志里 `Class2-1` 的 y=6.26、`ClassDirector` 的 y=6.01。「真实壁挂空调不会装到 4 米以上」→ 这两台是假锚点 → 气流飘在天花板上看不见。

甚至已经把 `IsMockAnchor()` 写完了：

```csharp
if (go.transform.position.y > 4f) return true;   // 真实壁挂空调不会装到 4 米以上
```

**幸好接进去之前先翻了房间里的候选清单。判断是错的。**

| 房间 | 地板参照物 | 地板 y | 空调 y | 离地 |
|---|---|---|---|---|
| Class1-2 | `Split01b` / `FlowerHolder01b` | ≈1.5 | 2.43 | 0.9 m |
| Class1-3 | `Split01c` / `FlowerHolder01b` | ≈1.5 | 2.58 | 1.1 m |
| Class1-4 | `Split01a` / `Blueprints05` | ≈1.5 | 2.57 | 1.1 m |
| **Class2-1** | `Table02` / `Radiator01 (3)` | **≈3.5** | 6.36 | **2.9 m** |
| **ClassDirector** | `TableOffice1` / `Radiator01 (2)` | **≈3.5** | 6.12 | **2.6 m** |

**`Interior` 里有两层楼，二楼地板在 y≈3.5。** 6 米对二楼是**正常吊装**，和一楼 0.9~1.1m 是同一种相对关系。

**接进去会怎样**：二楼两台被误判 → 跳过 L1 走 L2 → `TryFindAcByShape` 里有 `b.center.y ∈ [1.60, 3.40]` 的高度筛选 → **真实空调被排除** → 退回 L3 兜底「朝房间中心吹」→ 位置差得更多。**一个错误的判据会让两台本来正确的空调变得更差。**

## 八、已知局限与未做

### 8.1 已知局限

| 项 | 说明 |
|---|---|
| **两层楼高度差** | 判据里任何「绝对 y 值」都不可靠。`Interior` 二楼地板 y≈3.5，一楼 y≈1.5。今后写空间判据必须相对地板/房间包围盒，不能写绝对高度 |
| **笔记本喇叭频响** | 风噪下限压到 180Hz 是为了避开笔记本内置喇叭 150~250Hz 的死区。若接外接音箱，可以下探到 100Hz 让声音更「厚」，但当前值对答辩现场（大概率笔记本直放）更稳 |
| **5 台同开时的相位** | 5 条 clip 用同一个 seed 生成，同时开启时波形完全同相。听感上是「一个更响的声源」而非「5 台空调」。当前可接受（本来也不该分辨出 5 个独立声源），若要更自然可给每台加 seed 偏移 |
| **粒子不随房间气流场走** | 粒子只受 `Noise` 与重力，不感知房间里的桌椅/墙。穿模不可避免，但 0.26 的 alpha 下基本看不出 |

- **没改材质资产、没动烘焙、没动 `RenderSettings`**
- **没引入新依赖**（噪声用 `xorshift32` 手写，不碰 `UnityEngine.Random`）

- **屋顶积雪（bug 3）**已正式降级为已知局限，不在本包范围

## 九、如果重来一次（五条）

1. **「不像」的时候先对比参考图，不要先调参数。**
   我调了两轮（大小/透明度/密度/锥角）才想起来对照。范式错的时候，参数怎么调都不对。

2. **每隔几轮回到最基础的问题验证一次：它现在到底往哪个方向发射？**
   `shape.rotation` 那个 bug 伪装了六轮，因为方向错了以后现象仍然是「有粒子在飘」，而你会一直去调颜色和大小。Scene 视图的 Gizmo 一眼就能看出来。

3. **判据里的每根阈值，先问「这个数在本场景成立吗」。**
   「空调不装到 4 米以上」错在默认了单层楼。写好的判据，接进去之前再翻一眼实测数据 —— 这一步救了两台空调。

4. **音量这种「感觉量」，代码里算不出来也猜不出来。**
   我一开始想把它算准（「应该比提示音低多少 dB」），结果算出了一个听不见的值。该靠耳朵定的东西就别指望靠算式定。

5. **直觉给的算法，先用 Python 验一遍频响。**
   「两个低通相减做带通」听起来天经地义，实际低频不降反升；「噪声循环必须交叉淡化」听起来是常识，实际那才是唯一可听的变化。一个 10 行的 z 域计算就能否掉，比在 Unity 里反复试听快得多。
