### ① 关掉补光层 → 走廊几乎全黑，削顶归零

### ② 补光点距天花板仅 1.30m，辐照 1.39 倍，必爆

`IndoorFillLight.cs` 参数（**只读核对，未改动**）：

```
第 190 行  TubeFillDrop          = 1.14f
第 192 行  CorridorTubeRange     = 9.0f
第 193 行  CorridorTubeIntensity = 1.7f
第 195 行  RoomTubeRange         = 8.0f
第 194 行  RoomTubeIntensity     = 1.6f
第 197 行  HallTubeIntensity     = 1.3f
```

几何：

```
灯管中心      y = 3.34 m
补光点        y = 3.34 − 1.14 = 2.20 m      （第 487 行）
天花板        y ≈ 3.50 m
⇒ 补光点距天花板 d = 1.30 m
```

Unity 内置管线点光衰减 `1 / (1 + 25·d²/r²)`，r = 9.0、d = 1.30 → **atten = 0.657**，单管 `1.7 × 0.657 = 1.117`。

按走廊灯距 3.5m 累加相邻 6 管（`NdotL = d_vert / d`）：

| 水平偏移 | d | atten | NdotL | 贡献 |
|---|---|---|---|---|
| 0.0 m | 1.30 | 0.657 | 1.000 | 1.117 |
| ±3.5 m | 3.73 | 0.189 | 0.348 | 0.112 ×2 |
| ±7.0 m | 7.12 | 0.060 | 0.183 | 0.019 ×2 |
| ±10.5 m | 10.58 | 0.028 | 0.123 | 0.006 ×2 |
| **合计** | | | | **1.390** |

教室同算式（`RoomTubeRange 8.0` / `RoomTubeIntensity 1.6` / 灯距 3.0m）合计 **1.253**。

**全项目没有 Tonemapper**（`PPS_Bloom.asset` 的 `ColorGrading.tonemapper = { overrideState: 0, value: 0 }` = None，`gradingMode = 1` HDR）。任何 >1.0 的亮度被 `saturate` 硬截断成同一个纯白 ⇒ **1.39 倍必然 100% 削顶，吊顶板纹理必然消失**。与实测削顶 32.2% 吻合。

## 4. 修法对比（接手者直接照 §4.1 做）

### 4.1 方案 B —— 推荐，唯一正确解

**改 `IndoorFillLight.cs` 第 519~536 行 `CreateLight()`，3 处改动**：

```csharp
private Light CreateLight(string name, Vector3 pos, float range)
{
    GameObject go = new GameObject(name);
    go.transform.SetParent(transform, false);
    go.transform.localPosition = transform.InverseTransformPoint(pos);

    // ★ 新增 1：锥体默认朝下（Unity 的 Spot 默认朝 +Z，不是朝下）
    go.transform.localRotation = Quaternion.Euler(90f, 0f, 0f);

    Light l = go.AddComponent<Light>();
    // ★ 改动 2：Point → Spot
    l.type = LightType.Spot;
    l.color = FillColor;
    l.range = range;
    // ★ 新增 3：张角。140° 保证 9m range 的地面光池与现状一致（见 §4.2 核算）
    l.spotAngle = 140f;
    l.intensity = 0f;
    l.shadows = LightShadows.None;
    l.renderMode = LightRenderMode.ForcePixel;
    l.enabled = false;
    return l;
}
```

**为什么这是正确解**：

- **物理正确**。真实荧光灯有灯罩，往天花板方向本来就不发光。`IndoorFillLight.cs` 第 443~448 行的注释**自己就写了这句话**：

  > 「补光点比灯管低 1.14m：不放在灯管中心的原因：全向点光源离天花板只有 0.16m 会把管顶烧出白斑，真实荧光灯往上几乎不发光（灯罩兜着）。」

  它用「下移 1.14m」来**近似**「不往上发光」，**近似得不够**（1.30m 仍能打到 0.657 的衰减）。改成 Spot 朝下是同一物理事实的**精确表达**，注释与实现从此一致。
- **零副作用**。天花板在光源正上方、锥体之外 ⇒ 辐照 **0（降 100%）**；地面仍在锥体内 `NdotL = 1` ⇒ 辐照 **0% 变化**。
- **最小改动**。3 行。

**⚠ 必须同时验证的点**：`l.renderMode = LightRenderMode.ForcePixel`（第 533 行）与 Spot 是否冲突。理论上不冲突（Spot 也走逐像素路径），但请 play 确认墙面上没有出现「参数全对、画面不亮」的顶点光症状。

### 4.2 方案 B 的 spotAngle 取值核算（给接手者的定量依据）

补光点 y=2.20，地面 y=0，竖直距离 2.20m。要覆盖赤道方向 9m 半径的地面光池：

```
tan(θ/2) = 水平半径 / 竖直距离
若只覆盖单个灯管的圆形光池（半径 3.5m，= 灯距）：tan(θ/2)=3.5/2.20=1.591 → θ/2=57.8° → θ=115.6°
若要覆盖到 range 边界 9m：tan(θ/2)=9/2.20=4.09 → θ/2=76.2° → θ=152.4°
```

取 **140°** 是折中：`tan(70°)=2.747` ⇒ 地面覆盖半径 `2.20 × 2.747 = 6.04m`，大于灯距 3.5m 的一半覆盖需求，相邻灯管光池仍能无缝衔接；同时把 140° 以外的能量削掉（那部分原本是浪费在天花板上的）。

> **如果 play 后觉得墙面暗了**（Spot 的锥体外衰减会削掉墙面斜向光），把 `spotAngle` 往上调 10° 再试；**如果地面出现明暗环带**，说明两盏灯的光池没接上，同样往上调。
> 这两个现象都可逆，只改一个数，不必回退整个方案。

## 9. 我踩过的坑，接手者别重踩

1. **Unity Console 窗口是日志查看器，不能执行 C#。** 我连续三轮让主理人「把 `Debug.Log(...)` 粘进 Console」，全部落到搜索过滤框（显示 `No results for "..."`），三轮报废。**一切诊断入口必须做成热键或自动运行**（本工程已备好 F7~F12）。
2. **截图尺寸必须实测，不能假定 1080p。** 曾把 1919×1007 当 1080p，取样坐标落进编辑器深灰底（RGB 0.1765），把界面当成了画面。
3. **判「硬削顶」要三通道同时 >0.985 且饱和度 ≈ 0**，与「亮但有层次」区分开。
4. **`PostProcessVolume.profile` 是有副作用的 getter**（`PostProcessVolume.cs:120-138` 克隆并缓存 `m_InternalProfile`），与 `sharedProfile` 是两份对象。写错那个会改了不生效。
5. **`AddSettings` 会改资产**（`settings.Add` + `isDirty = true`）⇒ 写 `sharedProfile` 时绝不能调用。
6. **`softKnee` 会把 Bloom 阈值悄悄往前延伸** `lthresh × softKnee`，真正起点是 `lthresh − knee`，不是 `threshold`。0.90 + 0.30 ⇒ 有效起点 0.5512。
7. **Unity 不允许 MonoBehaviour 写成嵌套类**（`AddComponent` 会失败）。
8. **`OnGUI` 一帧调用 2~4 次，不能在里面 `new GUIStyle`** —— 这是最难归因的常驻掉帧源。
9. **场景 69 盏 Light 里 68 盏是 Rectangle Area**（type=3），内置管线**完全不产生实时光**，只有烘焙；而**该场景无任何 lightmap**。所以别去找这些灯。
10. **`RenderSettings.m_AmbientSkyColor = {1,1,1}` 纯白 + `m_AmbientMode = 0`（Skybox）**，白天天光主要靠它，这是白天 p50 稳定 0.765 的来源，**不是 bug**。
