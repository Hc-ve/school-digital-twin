### 2.3 真正的可疑点（按嫌疑排序，请逐个排除）

**嫌疑 A：`GetPixelAdjustedRect()` 与 `Place` 的坐标系不一致（最可能）**

`TwinSparkline.OnPopulateMesh` 用 `Rect r = GetPixelAdjustedRect()` 取绘制区。这是**像素吸附后**的 rect，与 `Place` 设的 `anchoredPosition/sizeDelta` 不是同一件事。若父级 Canvas 有缩放（本机为 `1.3x`，见 Unity 截图 "缩放 1.3x"），`GetPixelAdjustedRect` 返回的是**局部单位**、而 line 宽 `_lineWidth = 2.6` 是**绝对单位**，两者混用会让线宽在缩放下变形——但**不会造成 44px 平移**。

→ **请把 `r` 的实际值打出来一次**（`Debug.Log(r.xMin + "," + r.yMin + " w=" + r.width + " h=" + r.height)`），与 `Place` 传的值对比。若 `r.xMin != 0`（应为 0），则 pivot/anchor 有问题。

**嫌疑 B：`RectMask2D` 没罩住曲线**

窄态的 `Viewport` 挂了 `RectMask2D`（`TwinSystemPage.cs:561` 附近），但**曲线挂的是 `body`（= content），不是 viewport**。正常应被 content 的父级链裁掉。若曲线跑到标题区，说明**裁剪没生效**。

→ 请确认曲线节点在 `content` 下、且 `content` 的父链上有 `RectMask2D`。**若裁剪确实没生效，它就是"溢出面板右缘"的第一嫌疑。**

**嫌疑 C：`LoadFrom` 回填的点时间戳越界**

`span = clamp(now - t0, 1, 60)`，`tx = (s.T - left) / span`。若 `_aggPower` 里有 `T > now` 的点（时钟不一致、或 `Push` 与 `LoadFrom` 混用），`tx > 1` → `Clamp01(tx)` 会把它压到右缘 → **多个点堆在 x=right**，看起来就是"线贴右边缘还往外伸"。

→ 请确认 `_aggPower` 的时间基与 UI 的 `Time.unscaledTime` **同源**。若不是（比如用了 `Time.time` 或 `DateTime`），这就是**"断成两截 + 右端溢出"的唯一解释**：左段是历史（老时间基），右段是实时（新时间基），中间那段 `tx<0` 被 `continue` 跳过 → 视觉上就是断口。

**嫌疑 D：`AddFillQuad` 的 `bottom` 用了 `r.yMin`，而曲线值在量程外**

`vy = Clamp01((s.V - _min) / range)` 已 clamp，不会出 rect。但如果 `_min/_max` 是 `SetRange(0f, 30f)` **初始值**、而实际 `sum` 是 2800（W），则 `vy = Clamp01(2800/30) = 1` → **线贴顶边**。
→ 截图里的线**确实贴着填充块的顶边**，与此完全吻合。`UpdateStatsSpark` 里虽有自适应 `SetRange`，但它要求 `now >= _statsPowerNextAt` 且 `_tab == 4`；而 `RefreshStatsPage` 的 max/min 刻度读的是 `TryGetSparkRange`，其前置是 `_statsSpark.SampleCount >= 2`。**两者时序不一致 → 刻度空、线贴顶。**

> **结论：Q1 与 Q4（刻度不显示）很可能同源** —— 都是「量程没及时切到实际值」。**先修这个，再谈裁剪。**

## 6. Q7：Top5 全是 42W（P1，答辩可信度）

### 6.1 现象

全屏卡 D 五行：

```
1  2F203-001   42 W · 2%   ████████
2  1F108-001   42 W · 2%   ████████
3  1F107-001   42 W · 2%   ████████
4  2F204-001   42 W · 2%   ████████
5  1F103-001   42 W · 2%   ████████
```

五行全等、条形全满格。**`ratio = 该设备功率 / Top1 功率`，五个都是 Top1，于是全满。**

### 6.2 根因（已核实，不是实现 bug）

`MockDeviceAgent.cs:313`：

```csharp
case "Light":
    SetState(twinId, "Power", 42f);        // 量程 0~120W，警告线 110
```

**所有灯具都播种同一个 `42f`。** 而实际功耗应当区分（教室大灯 vs 走廊小灯 vs 应急灯）。于是 Top5 全是灯、全是 42W。

### 6.3 修法（只动 mock 播种，不碰口径）

按灯具**型号或面积档位**给不同播种值，例如：

```csharp
// 按 twinId 后缀或点位量程分档，避免全 42W
float seed = ResolveLightSeed(twinId);   // 例如 28 / 36 / 42 / 55 / 68
SetState(twinId, "Power", seed);
```

**最低要求**：让 Top5 出现**至少 4 个不同值**，且条长可见差异。
**更真实**：把空调（1.2kW）排进 Top1——但注意 **D5 单位缺陷未修前，空调会被算成 1.2W**，所以 `HasPowerReading` 会让它上榜但值极小。**这正是 D5 必须进 P6 的原因**，本轮不要指望 Top1 是空调。

> ⚠️ **不要为了让图表好看去改 `LivePowerOf` 或 `HasPowerReading`。** 那是 P6 的活，动了会让 KPI / 曲线 / 楼层三处同时变。
