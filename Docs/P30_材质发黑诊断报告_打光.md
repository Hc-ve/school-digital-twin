## 五、"Scene 视图纯黑 / Game 视图黑 + 细密噪点"的技术解释

两个视图的渲染路径差异**只有一个结构性来源**：

```
Scene 视图：  Unity 直接渲染 → 屏幕          （不走后处理）
Game  视图：  Camera → PostProcessLayer → 离屏 HDR RT → stopNaNPropagation → blit → 屏幕
```

而 `com.unity.postprocessing: 3.2.2` 是**新工程相对旧工程唯一新增的渲染相关依赖**（`manifest.json` 唯一差异）。

逐层拆：

| 现象 | 机制 | 置信度 |
|---|---|---|
| **Scene 视图纯黑** | 该面从烘焙图集拿到的光照贡献 ≈ 0（§4.2 的 A 通道 0.08）。Scene 视图不做任何补偿，如实呈现 → 纯黑 | 高 |
| **Game 视图同样纯黑** | 同上，底色没变 | 高 |
| **Game 视图多出"细密噪点"** | 三层叠加，按可能性排序：<br>① **PPS 离屏 RT 往返**：`finalBlitToCameraTarget: 0` 强制走 HDR 临时 RT，近零亮度区间被 8-bit 量化 + 双线性采样 → dither 状噪点<br>② **`stopNaNPropagation: 1`**：把 NaN/Inf 替换为纯黑，替换边界会形成细碎斑块<br>③ **8-bit RGBM/dLDR 光照贴图在 Linear 下暗部拉伸**：`m_EncodingQuality: 1`(Normal=RGBM) 与源 EXR 的 HALF 精度不匹配，近零区量化误差被放大 | 中 |
| **"无纹理"** | 光照为 0 时，`albedo × 0 = 0`，贴图再清楚也显示不出来。这与"材质贴图丢失"的观感**完全一样**，所以第一直觉会误判成材质问题 | 高 |

> **这就是为什么"看起来像材质坏了"但实际是光照问题**：黑是乘法的结果，不是 albedo 的结果。

## 九、附：8 类根因逐条判定（内置管线）

> **重要**：参考案例原文未能读取（§2）。以下 8 类是我依据任务包列出的比对项反推补全的，并逐条判断"能否在内置管线下复现"。**如与原文有出入，请补发原文，我重做本节。**

| # | 根因类别 | 能否在内置管线复现 | 本项目实测 | 判定 |
|---|---|---|---|---|
| 1 | `_Mode`（渲染模式）被重置 | **能**。内置 Standard 的 `_Mode` 同样控制 `_SrcBlend/_DstBlend/_ZWrite/关键字` 四件套，转管线时最容易丢 | 新旧完全一致：`0`×248、`1`×6、`2`×6、`3`×4、无字段×6 | **排除** |
| 2 | `_Cutoff`（裁剪阈值）被改 | **能**。Cutout 模式下 `_Cutoff = 1` 会把整块面裁掉（表现为隐形，不是黑） | `0.5`×263 为主，另有 `0.806`×2 / `0.59`×1 / `0.434`×1 / 无字段×3，全部合理 | **排除** |
| 3 | `_Glossiness` / `_Metallic` 丢失 | **能**。内置用 `_Glossiness`+`_Metallic`；**URP 用 `_Smoothness`+`_Metallic`**，转 URP 时 `_Glossiness` 会变成孤儿属性 → 光滑度归 0 | 新旧完全一致：`_Glossiness` 106×0.5 / 44×0 / 6×1.0；`_Metallic` 252×0 | **排除**（这条是**转 URP 特有**的，内置管线下属性名本来就不一样，不适用） |

| 5 | `_LightmapST` 丢失 | **内置管线不适用**。`_LightmapST` 是 URP 的 `Lit` shader 属性；内置管线的 lightmap ST 由 Unity 按 Renderer 内部设置自动传入，材质里**没有这个属性** | 材质里 0 处 `_LightmapST`（新旧皆然） | **不适用**（这条是**转 URP 特有**） |
| 6 | 贴图引用 GUID 断裂 | **能**。GUID 找不到 → 槽位变 `None`，材质退回纯色 | 10 个断裂 GUID，**新旧完全相同**（`ConcreteWall6e` / `GlassWhite`×2 / `Leather01`×2 / `TileArmstrong01_04On` / `Wood5` / `plants01a` / `DoorsWindowsPlastic`×2 / `ElectroWires01` / `SportFloor`） | **排除为本次成因**，但**是 2017 原始资产缺陷**，建议单独立项修 |
| 7 | Shader 引用丢失（粉红/黑） | **能**。表现为粉红，不是黑 | shader 引用 0 丢失：215×Standard(46)、47×Legacy(45)、3×Skybox(104)、7×其他内置 | **排除** |
| 8 | 色彩空间 Gamma ↔ Linear 切换 | **能，且是本次最可能的方向**。URP 强制 Linear，原 Gamma 工程切过去后全场景偏暗 | 项目**从一开始就是 Linear**（新旧 `m_ActiveColorSpace: 1`），不是"切换"造成；但 **2017 资产是按 Gamma 工作流产出的**（`LightingData.asset` 头部 `5.6.0f3`、`.meta` 是 `serializedVersion: 4` 的 Unity 5.x schema） | **成立，但性质不同**：不是转换引入，是**历史遗留** |

**小结**：参考案例走"转 URP"路线，其中第 3 类（`_Glossiness`→`_Smoothness`）和第 5 类（`_LightmapST`）是**转换过程本身引入的**，内置管线下不存在；第 1/2/4/6/7 类内置下可复现但本项目实测全干净；**唯一成立的是第 8 类，且性质是"2017 资产 + Linear 色彩空间"的历史遗留，不是转换引入。**
