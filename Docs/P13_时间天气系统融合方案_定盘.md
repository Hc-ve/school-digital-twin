4. 室温/湿度等数据跟着时刻与天气走（`TwinClimate` 已具备，只需接上）
5. 全程**不切场景、不重启、不报错**；判据全绿；主理人 play 通过

- ❌ 切到 Night 场景（F10，锚点归零）

## 3. 三条关键裁决

### 3.1 裁决 C-43：Shader 适配内置管线，改法按队员文档 §2.2 的对照表

> **冲突点**：队员包 2 个 Shader 是 URP 专用，本工程是内置管线。
> **裁决**：按队员技术文档 §2.2 给的对照表改写 `SnowGround.shader` / `WetGround.shader`：
> `LightMode=ForwardBase`、`#include "UnityCG.cginc"+"AutoLight.cginc"`、
> `GetMainLight → UNITY_LIGHT_ATTENUATION/_LightColor0`、`SampleSH → ShadeSH9`、
> `MixFog → UNITY_APPLY_FOG`、`TEXTURE2D/SAMPLER → sampler2D`。
> **理由**：对照表是队员在源工程实测过的，不是猜的；8 个 C# 文件零改动（只用 `Shader.Find`）。
> **影响**：断点改 2 个 Shader 文件；改完必须在**打包后**验一次（`Resources` 目录名不能改，否则剥离变粉）。

### 3.2 裁决 C-44：天气档位映射表（7 档视觉 → 4 档数据）

数据层 `TwinClimate.Weather` 保持 4 档不动（它的物理模型按 4 档标定过，动它要重算全年 192 组实算）。
视觉层用队员的 7 档预设，映射如下：

| 面板按钮（异环式 4 个） | 视觉档（EnvSample） | 数据档（TwinClimate.Weather） |
|---|---|---|
| 晴天 | `Clear` | `Sunny` |
| 雨天 | `Rain`（雷雨按钮不做，随机可摇出 `Storm`） | `Rainy` |
| 雪天 | `Snow` | `Snowy` |
| 随机 | `WeatherDirector` 权重链摇 | 按摇出的视觉档反查 |
| （无按钮，内部态） | `Cloudy` / `Overcast` / `Fog` | `Cloudy` |

> **理由**：数据层的 4 档是物理模型的输入（日较差、湿度、供暖），7 档里 Overcast/Fog 与 Cloudy
> 在物理上差异小于模型分辨率，硬拆是假精度。视觉层 7 档保留，自动轮换时天空才有层次。
> **影响**：断点写一张双向映射函数（约 20 行），**禁止**在 TwinClimate 里加档。

### 3.3 裁决 C-45：昼夜在 Day 场景内做，用「天空 + 雾 + 室内灯」三通道，不碰烘焙

打光 P30 证明改平行光/环境光对烘焙面无效。所以夜晚的「暗」不靠压暗场景，靠三件**真的看得见**的事：

| 通道 | 做法 | 为什么有效 |
|---|---|---|
| ① 天空与雾 | 队员包已含：运行时换 `Skybox/Procedural` + 夜晚叠乘（曝光×0.34、天空×0.20、蓝偏×1.7）+ 雾色压暗 | 天空盒是屏幕空间，永远生效 |
| ② 星空/云穹顶 | 队员包已含（`SkyDome` / `CloudDome`） | 同上 |
| ③ **68 盏室内 Area 灯** | 新增：夜晚（表盘 18:30~06:00）把 68 盏 Area 灯 `intensity` 从 0 提到设计值，白天压回 0 | Area 灯是**实时光**（`m_Lightmapping: 2` = Baked? 需施工确认；若为 Baked 则改无效，退化为只靠①②+窗光） |

> ⚠️ **F3 的坑在这里**：68 盏 Area 灯的 `m_Lightmapping: 2` 在 Unity 里 = **Baked**。
> 若确认是 Baked，通道③无效，夜晚只能靠①②——**那也是可以接受的**（天空黑+星空+雾，
> 室内保持现状亮度，读作「室内开着灯」，物理上说得通）。
> **施工第一步先验这 68 盏灯的 lightmapping 模式**，把结论写进回执，不要假设。
> 若要把它们改 Realtime 才能让夜晚室内变暗，**不改**（改 68 盏灯的烘焙模式 = 重烘 = 超期）。

### 3.4 裁决 C-46：修好 P30 的后处理死路（顺手，30 分钟）

> **冲突点**：P30 记录「后处理曝光 −4 EV 画面零变化」，结论是"PPS 不工作"。
> **真相**（本轮核实）：场景里**根本没有 PostProcessLayer / PostProcessVolume 组件**（F5）。
> 相机没挂 Layer，Volume 没挂组件，当然不生效。**不是引擎问题，是配置缺失。**
> **裁决**：给主相机挂 `PostProcessLayer`、建一个全局 `PostProcessVolume`（isGlobal=true），
> 把 P30 已写好的 `PPS_Bloom.asset`（含 ColorGrading/Bloom/Vignette）挂进去。
> 挂上后昼夜的曝光通道才真正可用（夜晚 `postExposure −1.05`）。
> **理由**：这是把一条已证死的路修通，成本 30 分钟，收益是夜晚整体压暗终于有手段。
> **风险**：挂 Layer 后若画面出现意外变化（色调/暗角），主理人 play 一眼能看出，回退只需删两个组件。
> **影响**：基线 D2「Bloom 静默失效」可一并结案。

## 4. 面板规格（给断点的硬约束）

> ⚠️ **本节坐标是负责人的占位稿。见微的图纸（`Docs/P13-1_时间天气面板设计图纸_见微.md`）落地后以见微为准**，
> 本节自动降级为「需求描述」（要什么控件、什么交互），不再作为施工坐标。
> 断点的面板施工（阶段二）**必须等见微图纸**，阶段一（移植/Shader/后处理）不等。

**入口**：总控抽屉工具行现有两项 `{ "数据源", "帮助" }`（C-42 裁过）。
**加第三项「时间天气」**，`ToolXs` 从 `{34,130}` 扩为 `{34,130,226}`。工具行高 80 不动（C-2）。

**面板形态**：不做全屏页、不做浮窗，做**抽屉内的一个页**（与五模块平级的第六页不行——
主理人裁过「页面层级不一样」）。所以：**点「时间天气」弹一个居中模态卡**（复用 `TwinSboDialog`
的模态骨架或 `TwinUIFactory.Rounded`），宽 420、高 300，Esc 可关。

**布局（照异环截图的逻辑，用本项目 token 重画）**：

```
┌──────────────────────────────────────────┐
│  时间天气                          [×]    │  标题 17 / FsSubtitle
│         ┌───────────┐                    │
│         │  ◯ 表盘    │                    │  直径 180，居中
│         │  13:00     │                    │  中心时刻 22 / FsDisplay
│         └───────────┘                    │
│  [随机] [晴天] [雨天] [雪天]               │  高 36，等分，FsBody
│  当前：白天 · 晴   室温 20.1°C            │  11 / FsCaption，读 TwinClimate
└──────────────────────────────────────────┘
```

- 表盘：`TwinUIFactory` 画圆环（代码生成，零图片资源），12 个刻度，
  指针 = 一个 9×9 圆点沿圆周摆位（`sin/cos`），**拖动 = 按住圆环区域移动鼠标**，
  角度 → 小时（0~24 连续）。中心文字实时显示 `HH:mm`。
- 拖表盘时调 `TwinClimate.SetHourOverride(hour, true)`；
  面板关闭或点「恢复真实时间」调 `SetHourOverride(0, false)`。
- 天气按钮调 `EnvironmentState.SetWeather(映射后)` + `TwinClimate.SetWeather(数据档)`，
  **两个必须同帧调**，否则天空在下雨、室温按晴天算。
- 选中态用 `TwinTheme.AccentDim` 底 + `AccentLine` 描边（与 chip 同款，不新造）。
- 色板一律走 `TwinTheme`，**禁止**从队员包带 `UIStyle/UITheme` 进来（它依赖的 UI 工具类我们没有）。

**禁止照搬的部分**：异环面板是全屏黑底 + 游戏 HUD 风格；我们是抽屉模态卡 + 科技蓝玻璃拟态。
**照搬的只有**：上表盘下天气条的信息结构、四档天气、拖动选时间的交互。
