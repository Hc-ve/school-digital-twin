## 1. R1 / R2：口径文案与实现相反（P0，最先做，10 分钟）

### 1.1 硬证据

**页脚**（`TwinFullLayer.Pages.cs:1120`）：

```csharp

```

**页面副标**（`Pages.cs:857`）：

```csharp

```

**但实际实现**（`Pages.cs:1208`）：

```csharp
// 【P5 口径统一】楼层能耗也改**实时**，不再是「额定 × 台数」。

// 而同一页的 KPI 写 2.8 kW（实时），差 8 倍 —— 评委一对账就穿帮。
// 现在和 KPI / 曲线走同一个 LivePowerOf，三个数字天然对得上。
float live = TwinPowerEstimate.LivePowerOf(a);
```

### 1.2 为什么这比 Q6 严重

Q6 是「两张卡的来源行要不要统一写含估算」，属于**措辞**。

R1 是**页面自己声明「这些数是估算的、不是实测」，而实际跑的是实时读数**。答辩时评委看到页脚这行字，会直接问：

> 「你这个 2.1 kW 是实时测的还是按额定功率估的？」

页脚写「估算：额定 × 台数」，KPI 却跑实时 —— **一句话就被拆穿，而且是我们自己写的字拆的。**

更糟的是它和 `LivePowerOf` 的注释直接矛盾。注释（`Pages.cs:1203`）明确写：

> 原来用 `RatedPower` 聚合 → 1F 14.4 + 2F 7.9 = 22.3 kW，而同一页的 KPI 写 2.8 kW（实时），**差 8 倍 —— 评委一对账就穿帮**。现在……三个数字天然对得上。

**当初改口径就是为了不穿帮，改完了文案没跟着改 —— 于是照样穿帮。**

### 1.3 改法

| 位置 | 现在 | 改成 |
|---|---|---|
| 页脚左段（1120） | `≈ 估算：按类型额定功率 × 台数  ·  刷新 0.5s · 采样 5Hz` | `实时读数 · 无读数设备按额定×0.15估算  ·  刷新 0.5s · 采样 5Hz` |
| 页面副标（857） | `设备分布 · 实时功率 · 楼层能耗 · 能耗排名（≈ 按额定功率 × 台数估算，非实测）` | `设备分布 · 实时功率 · 楼层能耗 · 能耗排名（实时读数为主，少数无读数设备含估算）` |

**文案取舍理由**（照抄，别自己改措辞）：

- 不能说「全部实测」—— `LivePowerOf` 对没 `Power` 读数的设备有 `RatedPower × 0.15` 兜底（暖气/门/传感器），那部分确实是估的。
- 不能说「估算」—— 主线是实时读数，写估算会抹掉主线（图纸 §2.5 已就同一个问题裁决过）。
- 取 **「实时读数 · 无读数设备按额定×0.15估算」**：主口径在前，估算成分点明，且把系数写出来（答辩被问「那部分怎么算的」能直接答）。

## 5. R7：Top5 全 42W（P1）

### 5.1 现象

全屏卡 D 五行全 `42 W · 2%`、条形全满格。`ratio = 该设备功率 / Top1 功率`，五个都是 Top1 → 全满。

### 5.2 根因（比 P5-4 里说的更深一层，**这条是本节重点**）

P5-4 说「所有灯具都播种同一个 42f」。核对后是**两层原因叠加**：

**第一层**：`MockDeviceAgent.cs:313` 所有灯播种同一个值：

```csharp
case "Light":
    SetState(twinId, "Power", 42f);
```

**第二层（更关键）**：`SetState` 写的是 `MockDataSource.SetOverride`，而 **override 一旦写入就永久生效**：

```csharp
// MockDataSource.cs:202
float overridden;
if (s_overrides.TryGetValue(Key(point.TwinId, metric.Metric), out overridden))
    value = overridden;   // ← 正弦波算出来了，然后被整个丢弃
```

`MockSignalGenerator.Next()` 每帧都在算正弦 + 噪声，但结果被 override 覆盖 → **44 个有 Power 的点位全是常量，波形从未生效。**

**所以"曲线是平线"和"Top5 全 42W"是同一个根因的两种表现。**

### 5.3 最小修法（本包只做这一步，不做载耦合）

**让 `Power` 播种后释放 override，交还给正弦波**：

```csharp
// SeedInitialState 末尾
// 播种的目的是"给场景一个初始值"，不是"把它永久钉死"。
// Power 是连续量（有用正弦波的意义）→ 播完交还给波形；
// 开关量（Open / OnCount / Ring / Brightness）保持钉死 —— 0/1 信号不能被正弦化。
```

> ⚠️ **必须提前知道的坑**：正弦波的均值是 `(Min + Max) / 2`，**不是播种值**。
> 灯的量程 0~120 → 正弦均值 = **60W**，而播种值是 42W。
> **释放 override 后灯会从 42W 跳到约 60W**，全楼总功率会跟着变。
> 这不是 bug，但要提前知道，否则会以为改坏了。
> 若要保持 42W 附近，需要改 `MockSignalGenerator` 的偏置 —— **那是 P6 的事，本包不做。**

**本包明确不做**：
- ❌ 不改 `LivePowerOf` / `SumLivePower` / `HasPowerReading` 三处口径
- ❌ 不做「灯按亮度算、空调按温较差算」的载耦合（那是口径变更，会影响 KPI 和榜单，须单独立项）
- ❌ 不修 kW/W 单位混用（D5，已入 P6）
