## 1. 现状诊断：10 个可验收问题

> 图：`01_现状诊断.png`。编号与下图一致。

### 1.1 逐条问题（现象 → 根因 → 改法）

| # | 问题 | 现象（截图证据） | 根因 | 改法（详见 §4/§5） |
|---|---|---|---|---|
| 01 | **信息重复** | L1 顶部三颗胶囊「在线 53 / 告警 2 / 受控 38」，下方三张概览卡又说一遍「设备总数 53 / 在线 53 / 告警 2」 | 头部摘要条与 KPI 行职责重叠，没有定义「谁是唯一数据源」 | 删掉胶囊条，头部只留标题 + 副标 + 右侧一行 11px 摘要；KPI 卡是唯一大数字 |
| 02 | **数值配色失控** | 概览卡里 28px 的纯绿「53」、纯红「2」，红块最抢眼，像 WinForm 控件 | 颜色被当成「装饰」而非「状态编码」，饱和度没有预算 | 数值一律回归 `TextPrimary` 白；颜色只出现在 3px 色条、胶囊、告警卡描边 |
| 03 | **主次入口失衡** | 「管」高饱和发光方块 vs「天」死灰方块；「预留」没有任何表达 | 缺少「主/次/禁用/预留」四态定义 | 主入口＝主色描边 + 柔光 + 左上角括号；次入口＝中性底 + 「预留」9px 角标 |
| 04 | **中部留白** | 图标格下方约 200px 全空，面板上重下空 | 面板没有第四段内容，留白不是呼吸而是「没东西」 | 补「实时动态」时间线（命令 / 告警 / 恢复 / 数据源），4 条 |
| 05 | **工具行越权** | 「数据源 / 录制 / 旧面板 / 帮助」与业务功能同字号同亮度，贴在面板最底部 | 调试项与业务项没有分层 | 工具行降为 11px 次要文字，调试项（数据源/旧面板）收进「设置」，工具行只留 4 项 |
| 06 | **面板是「平纸」** | 面板是一块纯色矩形，与 3D 场景之间只有一条硬边 | 没有渐变、没有网格、没有分区线、没有边界信号 | 三层发光公式（§3.5）+ 24px 网格底纹 + 左缘 2px 主色竖边 + 顶部 1px 高光 |
| 07 | **Tab 密度失衡** | L2 左侧 5 个 Tab 行高约 56，图标仅 28，选中态只有一圈细边 | 行高/图标/字号比例失配，选中态强度不足 | Tab 行高 44、图标 20（R6）、选中＝`AccentDim` 底 + 左 3px 竖条 + 主色字 |
| 08 | **空状态缺失** | 内容区是一个 408×388 的空黑箱 + 一行居中占位说明 | 没有空状态组件 | 统一空状态：线框圆 + 标题 13 + 说明 11 + 三点进度 + 「何时接入」 |
| 09 | **组件不统一** | L1 用大圆角方块、L2 用小方块；胶囊圆角/描边/字号各不相同 | 全项目没有 token，常量散落在 12 处 | 全部收敛到 `TwinTheme`：R8/R12/R16 + 6 档字号 + 5 态胶囊 |
| 10 | **场景层脱节** | 左下调试 HUD 是亮蓝实心块 + 灰块；触发钮是平涂蓝方块；小地图是硬边圆 | L0 没纳入设计体系，还是「调试工具」长相 | HUD 改芯片行（§5.7）；触发钮 48×48 圆角 + 四角括号 + 描边 + 角标；小地图加 1px 主色环 + 四向刻度 |

### 1.2 三条根因（决定改版策略）

1. **层级缺失** —— 所有信息平铺在同一层，没有「概览 → 模块 → 详情」的下钻；用户每做一件事都要先找。
2. **token 缺失** —— 颜色/字号/圆角/间距/动效全靠手写常量，12 处不一致，改一处破三处。
3. **留白误用** —— 空白不是呼吸，而是没有内容；面板上重下空，视线无处停留。

> **策略：先立 token（§3），再改布局（§4），最后补内容与动效（§5/§6）。** 顺序反了会返工。

## 2. 设计基准：成熟数字孪生项目的 6 条通用规范

> 调研对象：51WORLD 智慧校园驾驶舱、Hightopo 智慧园区/储能管控、Siemens Desigo CC、Schneider EcoStruxure、Johnson Controls OpenBlue、阿里 DataV / 腾讯 RayData、NVIDIA Omniverse。

| # | 规范 | 落地到本项目 |
|---|---|---|
| 1 | **单容器 + 内部页栈**（无多浮窗并列） | 一个抽屉容器，宽度 420↔640 动画；永不出现两个面板同时压场景 |
| 2 | **渐进披露**（点设备才出参数） | L1 只放入口；L2 放模块；L3a 详情卡贴左缘滑出 |
| 3 | **3D 与面板双向联动** | 面板宽度上限 640，永远给场景留 ≥36% 视野；详情卡与设备并置 |
| 4 | **6-3-1 配色** | 深色基底 60% / 科技青 30% / 告警暖色 ≤10%；警示色稀缺才有效 |
| 5 | **分级告警 + 处理状态** | 胶囊 5 态（在线/警告/告警/离线/未知）+ 告警「未确认/已确认/已恢复」 |
| 6 | **编号即主键** | 列表第一列永远是编号，等宽字体、可复制；编号贯穿台账—控制—告警—报表 |

**推论（本项目三条硬约束）**

- 深色是画布，**数据才是光源**：一个面板里只允许一个发光焦点。
- 任何「装饰」都必须能回答「它编码了什么信息」，否则删除。
- 全项目只有**一套**工具行、一套头部、一套胶囊、一套列表行。

**硬规则**

1. **禁用粉红 / 紫色**：与告警色相冲突，会把「选中」误读成「报警」。（现存 `TwinInteractMenu` 的 `(0.90,0.30,0.45)` 必须改掉）
2. 一个面板只允许一个发光焦点（选中项、告警卡、或主入口，三选一）。
3. 大数字永远白色；颜色只给 ≤3px 的色条、胶囊、描边。
4. 透明填充一律 ≤0.30 alpha，禁止大面积高亮色块。

### 3.2 字体层级（10 档 → 6 档）

| token | 字号 | 行高 | 用途 |
|---|---|---|---|
| `FsDisplay` | 28 | 34 | KPI 大数字、首页概览 |
| `FsTitle` | 22 | 28 | 页面标题、模块大数 |
| `FsSubtitle` | 17 | 24 | 区块标题、Tab 文案、模块名 |
| `FsBodyStrong` | 15 | 22 | 列表主文案、按钮 |
| `FsBody` | 13 | 20 | 副文案、图标名、胶囊 |
| `FsCaption` | 11 | 16 | 单位、脚注、时间戳、工具行 |

- 收敛映射：`11,12→11`、`13,14→13`、`15,16→15`、`17,18→17`、`22,23→22`、`26,28→28`。
- 中文：HarmonyOS Sans SC / MiSans / 思源黑体（TMP SDF，Fallback 必须挂一个中文字体）。
- **数字与编号一律等宽**（JetBrains Mono / Roboto Mono）：`53.28 kW`、`≈128.4 kWh`、`2F-201-灯具-001`。理由：纵向对齐、可复制、可核对。
- 标题字距 +2，大数字字距 +4（TMP `characterSpacing`）。

### 3.3 圆角 / 间距 / 尺寸

| 类别 | token | 值 | 用途 |
|---|---|---|---|
| 圆角 | `R8` | 8 | 行、按钮、Tab、输入框 |
| | `R12` | 12 | 卡片、KPI、图标底 |
| | `R16` | 16 | 抽屉、详情卡、模态 |
| | `Pill` | h÷2 | 胶囊、开关 |
| 间距 | `S4/S8/S12/S16/S24/S32` | 4 的倍数 | 面板内边距 16；卡间距 12；区块间距 24 |
| 描边 | `StrokeHair` | 1px `Border` | 所有卡片/行 |
| | `StrokeAccent` | 1px `AccentLine` | 仅选中/主入口 |
| | `BarAccent` | 2px `Accent`@0.38 | 抽屉左缘（唯一边界信号） |
| | `BarStatus` | 3px 状态色 | 卡片/KPI/列表行左侧 |

### 3.4 发光公式（零资源，纯 mesh 双层）

```
外层：圆角矩形，半径 = R + 3，描边 3px，色 = Accent @0.10
内层：圆角矩形，半径 = R，      描边 1px，色 = Accent @0.55
```

- 只允许用于：选中项、告警 KPI 卡、主入口、模态出现瞬间。
- **禁止** bloom 光斑、强投影、彩色外发光叠加。
- 告警态额外加「呼吸」：alpha 0.55↔1.0，周期 2.0s，`sin` 驱动，仅描边层。

### 3.5 动效（统一栅格）

| 动作 | 时长 | 缓动 |
|---|---|---|
| 抽屉滑入 / 滑出 | 240 / 180 ms | `easeOutCubic` / `easeInCubic` |
| 宽度 420↔640 | 200 ms | `easeInOutCubic` |
| 页推入 | 200 ms（旧页出 160） | `easeOutCubic` |
| 详情卡滑出 | 220 ms | `easeOutCubic` |
| 悬停反馈 | 120 ms | `easeOut` |
| 胶囊 / 页码点 / Tab 指示条 | 160 ms | `easeOut` |
| 数值变化 | 300 ms 滚动 | `easeOutCubic` |
| 告警呼吸 | 2000 ms 循环 | `sin` |

- 全部用 `Time.unscaledTime`（暂停时 UI 仍要动）。
- 禁止弹跳、回摆、缩放超过 1.04。
- 列表入场可 stagger 30ms/行，最多 8 行。

### 4.3 操作路径（改版核心收益）

```
改版前：点触发钮 → 开总控 → 找功能按钮 → 再进子面板            （4 步，3 次等待动画）
改版后：点触发钮 → 选模块 Tab                                 （2 步，1 次动画）
```

- L1 的「校园管理系统」入口是**唯一主入口**（主色 + 柔光 + 括号），其余入口一律次级。
- 场景层保留告警角标：**不打开面板也能看到异常**（这是侧边收纳方案唯一的「可见性」补偿）。

## 5. 组件规范

### 5.1 KPI 卡
- 尺寸 121×88（L1）/ 216×88（L2）；`R12`；`CardTop→CardBottom`；`Border` 1px。

### 6.2 关键技术点

1. **网格底纹**：生成 64×64 `Texture2D`（每 24 单位一条 1px 白线，alpha 0.02；每 120 单位一条 alpha 0.045），`Sprite.Create(..., SpriteMeshType.FullRect)` 后 `Image.type = Tiled`。**全项目只生成一张**，静态缓存。
2. **发光**：不要用 shader/bloom。用 `TwinRoundedRect` 画两层（外 3px@0.10，内 1px@0.55），外层半径 +3。发光层 `raycastTarget=false`，静态不重建。
3. **渐变**：`TwinRoundedRect` 已支持顶点色渐变，直接给 top/bottom 两色。
4. **数字滚动**：`Mathf.Lerp(prev, next, easeOutCubic(t))`，300ms，`t` 用 `Time.unscaledTime`；值未变不写 `Text.text`（避免每帧重建）。
5. **Canvas 拆分**：`Canvas_HUD`（场景层，`sortingOrder=10`）/ `Canvas_Drawer`（20）/ `Canvas_Modal`（30）。抽屉滑入只重建 Drawer 层，不连累 HUD。
6. **TMP 字体**：中文字体 Fallback 必须挂；数字用等宽字体资源，`fontFeatures` 关闭连字。
7. **性能红线**：单帧 `SetVerticesDirty` ≤ 4 次；列表 > 40 行必须虚拟化；动画期间禁止 `LayoutRebuilder.ForceRebuildLayoutImmediate`。

### 6.3 禁止事项（会直接判不合格）

- ❌ 引入任何图片资源（图标、纹理、光晕图）——必须纯代码生成。
- ❌ 改 `TwinUIState` 的仲裁语义、改层级栈、改编号规则、改命令状态机。
- ❌ 在代码里出现第二套颜色/字号字面量（必须走 `TwinTheme`）。
- ❌ 大面积 bloom、彩色外发光、粉红/紫色、渐变方向混乱（只能垂直）。
- ❌ 让面板遮住 > 64% 视野；让两个面板同时可见。

## 附录 A · 半透明 token 标定表（P29-2）

> 本工程 `ProjectSettings/ProjectSettings.asset` 里 `m_ActiveColorSpace: 1`（**Linear**），
> UGUI 混色在线性空间完成，同一个 alpha 上屏后的观感比设计稿的 sRGB 百分比亮 **2~3 倍**。
> 所以本表**不以 alpha 为准，以截图取色的亮度差 Δ 为准**（Δ = 采样点亮度 − 面板底色亮度，
> 亮度 = 0.299R + 0.587G + 0.114B，面板底色取面板上下两点均值）。
>
> 采样方法：批处理建一块 960×680 的同款渐变面板，把候选 alpha 各铺一块 120×20 的色块，
> 用 `Unity.exe -batchmode -executeMethod ...` 渲染到 RenderTexture 存 PNG，
> 再用 System.Drawing 逐点取色反解。方法可复现，脚本用完即删（不入库）。

※1 `AccentDim` **按亮度差标定，不按 R 通道**。主色 R 分量最低（0.20），按「Δ_R = 14–20」反解要
   alpha 0.30 —— 实测那一档上屏是一整条饱和蓝（(31,112,151)），做选中行底会把整行点亮；
   而 Δ 梯队 4-8 / 6-10 / 10-14 / 14-20 / 16-24 / 60-90 只有在**统一按亮度**衡量时才自洽。
   若坚持 R 通道口径，把 `AccentDim` 改回 `WithAlpha(Accent, 0.30f)` 即可，其余代码不用动。

※2 `ChartGrid` 需求写的是「白 @0.09」，实测 Δ≈64 —— 比卡片描边还亮，会盖住折线。
   按标定纪律取 Δ11.5。它和 `GridLine` 分工明确：`GridLine` 只服务 `TwinPaint.GridSprite`
   烘进贴图的那张网格，**禁止**拿去画图表。

※3 `TopHighlight` 两个数：28.2 是对「面板顶边局部底色(26.1)」，31.7 是对「面板上下均值(22.6)」。
   两种口径都落在 28–32 内。

**一条要记住的坑**：烘进 8bit 贴图的 token（网格、渐变）实际生效值是 `round(alpha×255)/255`，
相邻两档可能差 5 个 Δ（`0.004 → Δ7.5`、`0.006 → Δ11.5`，中间没有档）。
顶点色的 token 不受此限，可以连续微调。

**还债记录**：`TwinButton.cs` 禁用态原为 `WithAlpha(Border, 0.35f)`。
`WithAlpha` 是「把 alpha 设成 0.35」而**不是**乘 0.35 —— Border 已是白 @0.006（Δ11.5），
乘上去成了白 @0.35（Δ≈90），禁用按钮反倒成了全屏最亮的一圈描边。已改为直接引用 `Border`，
禁用态只靠「底 0.35 + 字 Muted」表达。
