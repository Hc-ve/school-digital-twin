## 1. 规格一 · 两处高度溢出修复

### 1.1 先给结论：预算没算错，是容器没被约束住

按现有常量推算，两处**本来都不溢出**：

| 区域 | 现有常量（页面坐标） | 下沿 | 内容底 544 | 判定 |
|---|---|---|---|---|
| L1 时间线 | 首行 312，4 行 × 52 = 208 | **520** | 544 | 余 24，理论不溢出 |
| L2 异常 Top3 | 行 368/414/460，高 40 | **500** | 544 | 余 44，理论不溢出 |

而 play 截图里两处都被工具行压住 → **溢出发生在容器层**，不是行高预算。断点按 1.3 的三条诊断项逐条排查，不要先改行高。

### 1.2 不变量（四条，必须同时成立）

| # | 不变量 | 数值 |
|---|---|---|
| I1 | 抽屉 720 拆分为 头部 96 / 内容 544 / 工具行 80 | 96 + 544 + 80 = 720 |
| I2 | 页面根 RectTransform：`anchorMin(0,0)`、`anchorMax(1,1)`、四边 offset 全 0、**`sizeDelta = (0,0)`** | 由 `_content`（已扣 80 / 96）决定，页面**不得**设固定高度 720 |
| I3 | 页面内元素一律「页面顶为 0、向下计」的绝对 y（`TwinUIFactory.Place` 语义），**禁止底部锚点堆叠** | — |
| I4 | 任何内容下沿 ≤ **528**（距内容底留 16 安全区）；工具行分隔线 y=640 以上 16px（624–640）**禁止有内容** | 528 / 624 |

### 1.3 诊断清单（按顺序，先查不查）

| 顺序 | 检查项 | 期望 | 不符即结论 |
|---|---|---|---|
| ① | 运行时打印 `page.rect.height` | **544** | 若为 720 或 640 → 页面根没继承 `_content`，I2 被违反 |
| ② | 打印 `page.pivot` / `page.anchoredPosition` | pivot(0,1) / (0,0) | pivot 为 (0.5,0.5) 时，所有绝对 y 会整体下移约 272 |
| ③ | 打印最后一行 `GetWorldCorners()` 与工具行上沿 | 行下沿 − 工具行上沿 ≥ 16 | 差值 <16 即溢出，继续查 ④ |
| ④ | 该行是否用了 `anchorMin.y = 0`（贴底） | 应为 1（贴顶） | 贴底会让最后一行正好落在内容底 544 上，副文案（+20）越过 640 |

### 1.4 修复动作（三选一按诊断结果，全部需加）

| 动作 | 做法 | 为什么 |
|---|---|---|
| A1 | 页面根统一走 `TwinUIFactory.Stretch(page, 0,0,0,0)`，禁止任何固定高度 | 从源头消灭"页面比容器高" |
| A2 | `_content` 上加 `RectMask2D`（**不加在 `_root`**） | 越界内容被裁在工具行之上；加在 root 会把发光描边一起裁掉 |
| A3 | 加运行时断言：最后一行下沿 ≥ 工具行上沿 +16，不满足 `Debug.LogError` | 下次再溢出，日志直接指出来，不靠肉眼 |

## 2. 规格二 · 统计口径 UI 呈现规则

### 2.1 唯一口径

**设备数 = 已接入 `TwinRegistry` 且 `Active == true` 的锚点数量。** 当前 53；P3 路灯接入后自动变 153，**不改代码**。

### 2.2 每个数字的取数定义

| 显示位 | 值定义 | 取数 | 允许写死 |
|---|---|---|---|
| L1 KPI「设备总数」 | 口径总数 | `ActiveDeviceCount` | ❌ |
| L1 KPI「在线」 | Active 且 `Status ∈ {Normal, Warning, Alarm}` | 同上集合按状态过滤 | ❌ |
| L1 KPI「告警」 | **未确认**告警数（已确认/已恢复不计） | `AlarmCenter` 未确认集合 | ❌ |
| L1/L2 摘要「在线/告警/受控」 | 同上；受控 = 受控范围内设备数 | 同上 | ❌ |
| L2 KPI「在线/告警」 | 同上 | 同上 | ❌ |
| L2 楼层健康三段 | 同一 Active 集合按楼层分组计数 | 同上集合 + Zone | ❌ |
| L2 异常 Top3 | 未确认告警按严重度降序取前 3 | 同上 | ❌ |

### 2.3 五条硬规则

| # | 规则 | 说明 |
|---|---|---|
| R1 | 总数 = 在线 + 离线 | 三数必须自洽；离线 = Active 但 `Offline/Unknown` |
| R2 | 健康条三段之和 **必须等于** 设备总数 | 不等则整卡转「无数据态」，不许画一条假的条 |
| R3 | 告警计数只算「未确认」 | 已确认仍在列表里，但不进红数；否则"确认"按钮等于没用 |
| R4 | 副标注明口径 | L1 副标固定格式：`1号教学楼 · 已接入 53 台 · 室内 + 室外路灯` |
| R5 | UI 代码里禁止出现设备数字面量 | `53 / 151 / 153 / 38` 一律走取数 |

### 2.4 口径变更时的表现

| 场景 | 期望表现 |
|---|---|
| P3 路灯接入（53 → 153） | 所有数字自动跟随；健康条多出「室外」段；无需改 UI |
| 某设备被禁用（Active=false） | 总数与在线同减 1，健康条总和同步 |
| Registry 未就绪（启动首帧） | 全部走无数据态（规格五），**不显示 0** |

**【验收标准】** 同屏截图内所有「设备总数」取值一致（L1 KPI = 摘要 = L2 KPI）；健康条三段数字相加等于 KPI 总数；`grep -rn "53\|151\|153" Assets/_Project/Scripts/UI` 不出现于 UI 文案。

## 4. 规格四 · 告警卡重绘

### 4.1 问题

整圈 1px 红描边在本系统里的既有语义是「你选中了它」。告警态用整圈框 = 把「出事了」画成「被选中」，两种语义撞车。

### 4.2 新规格（四个元素替代一圈框）

| 元素 | 规格 | 色值 |
|---|---|---|
| 左色条（常态） | x=12、y=14、**3×32**、R1.5 | `#596173`（StatusUnknown） |
| 左色条（告警） | x=12、y=14、**5×32**、R1.5 | `#E63939` |
| 顶部渐变条（仅告警） | x=12 → width−12、y=0 → 2（高 2） | 左端 `#E63939` 100% → 右端 0%，横向线性 |
| 数值（仅告警） | 字号 28 不变 | `#E63939` |
| 卡底 / 描边 | 不变（CardTop→CardBottom + Border） | — |
| 呼吸 | 仅作用于「色条 + 数值」的 alpha，**0.6 ↔ 1.0**，周期 2000ms，`sin` | — |

**取消**：`AlarmStroke` 不再用于卡片边框（token 保留，供别处用）。**禁止**给整卡加红色底（会让卡片变粉，与"深色为画布"冲突）。

### 4.3 三种状态对照

| 状态 | 色条 | 顶部渐变 | 数值色 | 呼吸 |
|---|---|---|---|---|
| 正常（在线） | 3×32 `#596173`（StatusUnknown） | 无 | `#F0F5FC` | 无 |
| 告警（未确认 >0） | 5×32 `#E63939` | 有 | `#E63939` | 有 |
| 无数据 | 3×32 `#596173` | 无 | `#75859C` | 无 |

**【验收标准】** 告警卡四边取样（原边框位置）与卡内底色 Δ ≤ 3（即确认无整圈亮边）；左色条宽度 5±0.5px、Δ ≥ 60；顶部渐变左端 Δ ≥ 40、右端 Δ ≤ 8；连续两帧（间隔 1s）数值 alpha 不同且落在 0.6–1.0。

## 5. 规格五 · 无数据态

### 5.1 适用对象

`总功率`、`今日用电`（P5 聚合 sink 落地前恒为无数据）；以及 Registry 未就绪时的所有 KPI。

### 5.2 规格

| 元素 | 规格 | 色值 |
|---|---|---|
| 数值位 | 显示 `—`（U+2014 em dash），字号同正常（28），**不是** `0` / `0.00` / `--` / `N/A` | `#75859C` |
| 单位位 | **隐藏**（避免 `— kW` 被读成"零千瓦"） | — |
| 说明 | 卡内左下、9px：`数据源未接入` | `#75859C` |
| 色条 | 3×32 常态灰，不呼吸 | `#596173` |
| 描边 | 保持 Border（白@2/255），不加红框 | — |

### 5.3 为什么不用 0 / --

- `0` 会被读成"真实读数 0"，答辩时最容易被追问"为什么功率是 0"；
- `--` 信息量不足，看不出是"没接"还是"断了"；
- `—` + 一句说明，等于把"还差什么"写在了脸上。

**【验收标准】** 无数据卡截图里数值为单个 em dash、单位区为空、说明文字存在且 ≤9px；数值与说明取样均为 `#75859C`（Δ vs 卡底 20–30）；全局搜索无 `0.00` / `--` / `N/A` 占位文案。

## 8. 给断点的实现约束（不是代码，是边界）

1. **不要动 token 值**（除 `GridLine` 停用）；本轮的色值全部是既有 token 的引用。
2. 页面根高度只能是 544，**不要**用 720 或 `Screen.height`。
3. `RectMask2D` 加在 `_content`，**不加 `_root`**（否则发光描边被裁）。
4. 溢出断言用 `GetWorldCorners()`，不用 `rect`（布局未刷新时 `rect` 不可信，见 P00 §1.6 B3）。
5. 改完在报告里附：`page.rect.height`、最后一行四角坐标、工具行上沿坐标三组数——没有这三组数，验收不通过。
