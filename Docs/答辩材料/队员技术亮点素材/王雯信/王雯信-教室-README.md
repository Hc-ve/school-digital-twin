## 1. 项目背景与定位

### 1.1 业务场景

学校要改建一间普通教室为计算机机房，需要同时交付三样东西：

1. **可施工的平面与家具方案**——座位怎么排、桌子多大、线怎么走、灯怎么布；
2. **可评审的三维效果**——让非专业的校方、施工方在纸上就能看懂空间关系；
3. **一份能直接发给多方的方案书**——图文表格齐全，不依赖任何专业软件就能打开。

传统做法是三拨人分工：室内设计师画 CAD，效果图公司建模渲染，再由人把数字抄进 Word。这套流程的三个死穴是：**尺寸改动无法传导**（改了桌深，平面图、剖面、清单、文字全要手改）、**效果图与图纸不一致**、**文档数字靠手抄必然出错**。

### 1.2 要解决的核心问题

| 问题 | 本项目的解法 |
|---|---|
| 尺寸散落在图纸、模型、文档三处，改一处就失同步 | 全部尺寸收敛到 `lab_lib.py` 顶部常量，几何、渲染、文档三层都从同一份常量派生 |
| 效果图角度靠试，剖切图/平面图要另做一套 | 相机封装成 `shoot()`，可见性封装成三套「隐藏名册」，11 个视角一次跑完 |
| 排布方案说不清代价（能坐多少人、为什么不能更多） | 把「面积 × 座位 × 朝向」的约束写成可计算的排布函数，结论直接落进文档第 3 章 |
| 方案书排版与内容耦合，改一个数字要重排全文 | 模板只放版式、用 `@@TOKEN@@` 占位，脚本负责注入数据与图片，模板与内容解耦 |
| 交付物在别人电脑上打不开（缺字体、缺图、缺插件） | 图片全部 base64 内嵌、矢量图内联 SVG、字体用系统字体栈，产出**单文件 HTML** |

### 1.3 定位边界

这是**设计交付工具链**，不是运行时软件：没有 UI、没有交互逻辑、没有存档。它的「使用者」是设计师本人，输入是一组尺寸常量，输出是图纸与文档。因此本 README 里说的「功能」，指**工具链能力**，不是玩家可操作的功能。

### 3.2 坐标与单位约定

| 约定 | 取值 | 影响 |
|---|---|---|
| 单位 | 1 Blender 单位 = 1 m | 导出 FBX/glTF 到引擎时无需缩放 |
| X 轴 | 开间方向（桌长 1400 沿 X） | 排布横向坐标 `LAYOUT_X` |
| Y 轴 | 进深方向，**-Y 为讲台侧** | 排布纵向坐标 `LAYOUT_Y`，座位 `rot_z = π` 统一朝 -Y |
| Z 轴 | 高度，地面 Z = 0 | 桌面 0.75、窗台 0.90、门高 2.10、净高 3.20 |
| 单体原点 | 课桌原点在**桌底中心** | 复制时只需给 (x, y)，不用补偿高度 |

### 3.3 关键实现逻辑

**(1) 单一数据源 + 单向派生。** 所有尺寸只在一处定义，上层脚本一律 `import lab_lib as L` 读取，不复制数值：

```python
# lab_lib.py
ROOM_W, ROOM_D = 8.4, 9.0
LAYOUT_X = [-3.10, -0.70, 0.70, 3.10]     # 4 列
LAYOUT_Y = [-2.650, -1.125, 0.400, 1.925] # 4 排 → 16 桌 / 32 座
L, D, H = 1.400, 0.700, 0.750             # 桌长 / 桌深 / 桌高
```

`build_all.py`（单体三视图）与 `build_classroom.py`（整间教室）都调用同一个 `layout_positions()`，因此两张图里的座位永远一致——这是「改一处、全链跟着变」的实现基础。

**(2) 链接复制代替复制粘贴。** 16 张桌子如果各自建几何，面数和文件体积会翻 16 倍。`place_desk()` 用「复制对象、共享网格」的方式实例化：

```python
def place_desk(parts, offset, rot_z, tag):
    R = Matrix.Rotation(rot_z, 3, 'Z')
    for key, ob in parts.items():
        n = ob.copy()
        n.data = ob.data              # ← 共享 mesh，16 张桌只存 1 份几何
        bpy.context.collection.objects.link(n)
        n.location = R @ ob.location + Vector(offset)
        n.rotation_euler = (0.0, 0.0, rot_z)
```

结果：16 张桌共 64 个对象，但只引用 4 份网格数据，32 座教室的 `.blend` 只有 204 KB。

**(3) 材质节点用 `bl_idname` 定位，不用名字。** 中文界面下节点名会被本地化成「原理化 BSDF」，`nodes.get("Principled BSDF")` 会返回 `None` 并**静默失败**（材质看起来建好了，颜色却没生效）：

```python
b = next((n for n in nt.nodes if n.bl_idname == 'ShaderNodeBsdfPrincipled'), None)
```

插槽名（`inputs['Base Color']`）仍是英文，可以放心用。

**(4) 相机封装 `shoot()`，一次调用一个视角。** 透视用 `to_track_quat('-Z','Y')` 自动对准目标点，正交用于平面图：

```python
cam.rotation_euler = (Vector(target) - Vector(loc)).to_track_quat('-Z', 'Y').to_euler()
if ortho:
    cd.type, cd.ortho_scale = 'ORTHO', ortho   # 平面图必须正交，否则 2 m 高的大屏会投成大片遮挡
```

平面图额外传 `euler=(0, 0, math.pi)`，保证「讲台在上」而不是左右翻转——用 `to_track_quat` 顶视会产生不确定的偏转。

**(5) 可见性用「名册」管理，而不是逐个 `hide_render`。**

```python
CUT_AXON  = ["Wall_B", "Wall_L", "Ceiling", "Sky_Backdrop", "Out_Ground"] + LAMP_MESH
CUT_PLAN  = ["Ceiling"] + LAMP_MESH
WALL_MOUNT = ["BigScreen_Frame", "BigScreen_Panel", "Speaker_-1", ...]
```

关键点：名册里**只放灯具实体（mesh），绝不放 AREA 灯（light）**。早期把灯具和光源一起隐藏，剖切图里室内直接变黑。

**(6) 文档组装：模板与数据彻底分离。** `doc_template.html` 里只写版式与 `@@TOKEN@@`，`build_doc.py` 负责替换并自检：

```python
for token, fn in (("@@SVG_DIMS@@", "svg_dims.svg"), ...):
    html = html.replace(token, read(os.path.join(LAB, fn)))
for token, fn in (("@@IMG_DESK_ISO@@", "desk_iso.jpg"), ...):
    html = html.replace(token, b64img(os.path.join(WEB, fn)))
left = sorted(set(re.findall(r"@@[A-Z_]+@@", html)))   # 漏替换会在这里暴露
```

实测输出：`bytes: 1337231`、`unresolved: []`、耗时 **494 ms**。

### 3.6 关于 Unity 版本

本项目**不是 Unity 工程**，没有 Unity 版本号，也不依赖任何 Asset Store 资源。它是「Blender 侧的设计生产链」，产物是图片与 HTML。

如果这个方案后续要并进 Unity 答辩工程，需要做的三件事（都有明确代价，不是改个后缀就行）：

| 事项 | 说明 |
|---|---|
| 几何导入 | 导出 FBX 时勾选 Bake Axis Conversion（Blender Z-up → Unity Y-up）；模型为米制、无缩放，导入后 1 单位 = 1 m 可直接用 |

## 4. 三个亮点功能

### 4.1 亮点一：一张参数化双人课桌，复制出 32 座

![课桌单体三视图渲染](images/highlight-01-desk.png)

**是什么。** `build_desk(M)` 用 40 个 box + 2 个圆柱拼出一张 1400×700×750 的双人钢木桌，包含桌面、后缘 80 mm 走线槽与蓝色盖板、4 条 40×40 方管腿、4 根横梁、桌下 100×50 线槽、2 个 φ60 穿线孔、2 套主机吊架（离地 200 mm）、2 台显示器、2 套键鼠。所有零件最后 `join()` 成 4 个网格组：桌体 / 屏幕 / 键鼠 / 主机。

**实现原理。** 三个设计决定让「一张桌子」变成「一套可复用的座位单元」：

1. **尺寸全部来自模块常量**（`L/D/H/LEG/LEG_X/RAIL/SEAT_X`），改桌深只需改 `D`，桌面、走线槽、横梁、主机吊架会一起跟着变，不会出现「桌深改了但横梁还悬空」；
2. **原点归到桌底中心**，`place_desk()` 只需给平面坐标和旋转角，不用为每张桌补 Z 偏移；
3. **网格分组**把「结构」和「设备」拆开——做平面图时可以只隐藏屏幕和键鼠保留桌子，做设备清单时可以按组统计数量。

倒角由 `bevel()` 统一施加（0.003 m / 2 段 / 40° 角度限制）并立即 apply，因此导出给任何渲染器都带倒角，不依赖修改器栈。

### 4.2 亮点二：把「面积 × 座位 × 朝向」的冲突算清楚，并用三套可见性出图

![剖切轴测：32 座排布与建筑围护](images/highlight-02-layout.png)

**是什么。** 最终方案是**单向横排 + 中间两条纵向过道**：4 排 × 8 座 = 32 座，横向 400 边距 | 1400 桌 | 1000 过道 | 1400+1400 | 1000 过道 | 1400 桌 | 400 边距；纵向讲台前区 1500 + 4×700 桌深 + 3×825 排间净距 + 后走道。同时产出剖切轴测、正交平面、完整围护外部轴测、两个反向室内广角共 6 个教室视角。

**实现原理。** 排布不是「摆着看顺眼」，而是一个有约束的求解：

- 座位数 = 列数 × 排数 × 2；列数由「桌宽 + 过道 + 边距 ≤ 8400」决定，最多 4 列；
- 排数由「讲台前区 + n×700 + (n-1)×825 + 后走道 ≤ 9000」决定，最多 4 排；
- 因此**单向朝前在 75.6 ㎡ 里只能坐 32 人**；要 48 座必须放弃单向（改背靠背，两排共用背边），或把房间扩到约 102 ㎡。这条结论直接写进了方案书 3.3 节，答辩时能回答「为什么不是 48 座」。

出图侧的关键是**同一份场景、三套可见性**：剖切图隐藏后墙/窗墙/吊顶（保留右墙，否则贴墙的机柜会悬空）；平面图隐藏吊顶与全部墙挂设备（否则 2 m 高的大屏在正交投影下会盖住半个房间）；外部轴测一个都不隐藏，用来证明「四面墙、窗玻璃、门、吊顶都建全了」。**单一透视画面不可能同时呈现四面墙**——室内看不到身后，室外近侧墙挡住室内，所以用两个反向室内广角（`10_class_wide` 看讲台、`11_class_back` 回看后排）合起来覆盖。

### 4.3 亮点三：一条命令把 11 张图 + 3 张矢量图组装成 1.34 MB 单文件方案书

![方案书首屏（浏览器实开截图）](images/highlight-03-doc.png)

**是什么。** `build_doc.py` 把模板、3 张手写 SVG、11 张 JPEG 合成一个 `机房课桌设计方案.html`：13 章、13 张表、3 张矢量图、11 张渲染图，全部内联，**1,337,231 字节**，双击即开、可直接打印成 PDF、微信发送不丢图。

**实现原理。** 采用「模板占位 + 构建期注入」：模板里只有版式与语义结构，图片位置写 `@@IMG_CLASS_CUT@@` 这类 token；构建脚本把 JPEG 读成 base64 data-URI、把 SVG 文件原文插入，替换完成后用正则 `@@[A-Z_]+@@` 扫一遍残留并打印。这样做的收益是**改内容不动版式、改版式不动脚本**：重排章节只改 HTML 模板，换图只改 `lab/web/` 下的文件，二者都不需要碰 Python。

组装耗时实测 **494 ms**，输出自检 `unresolved: []`。方案书的 3 张矢量图（尺寸标注、桌面分区、走线系统）是手写 SVG 而不是渲染图，原因是标注线在 300 dpi 打印时必须保持锐利，位图放大会糊。

## 5. 踩坑日志

### 5.1 速查表

| # | 现象 | 根因 | 解决 |
|---|---|---|---|
| 1 | 材质颜色怎么改都不生效，界面里看着是灰白 | 中文界面下节点名被本地化为「原理化 BSDF」，`nodes.get("Principled BSDF")` 返回 `None`，代码走了新建分支但没连线 | 一律用 `n.bl_idname == 'ShaderNodeBsdfPrincipled'` 定位节点 |
| 2 | 木色发灰发白，像蒙了一层雾 | Blender 5.x 默认色彩变换是 AgX，会压暗饱和色 | `scene.view_settings.view_transform = 'Standard'` |
| 3 | 改了 `lab_lib.py` 重跑，结果还是旧的 | 同一 Blender 会话里模块已被 `import` 缓存 | `sys.modules.pop('lab_lib', None)` 后重新 exec |
| 4 | 窗户永远渲染成一块白板，看不到玻璃 | 窗框建成了实心方块，把整个窗洞堵死，玻璃包在里面 | 窗框改成上/下/左/右 4 条边框条围合 |
| 5 | 剖切图和平面图里室内一片黑 | `hide_render` 把灯具的**光源**一起关了 | 名册只隐藏灯具 mesh，保留 AREA 灯 |
| 6 | 平面图上出现大片斜向遮挡 | 用透视相机拍顶视，2 m 高的大屏投成大块阴影 | 改正交投影 `cd.type='ORTHO'`，并隐藏墙挂设备 |
| 7 | 外部轴测渲染出一整片纯蓝，像材质坏了 | 新加的室外相机跑到了天空背景板背面 | 背景板从 x=-8.3 移到 x=-14.3 并放大到 34×26 |
| 8 | 无论怎么调机位，总有一面墙拍不到 | 单一透视视角的几何限制：室内看不到身后，室外近墙挡室内 | 出两个反向室内广角 + 一张外部全景，组合覆盖 |
| 9 | 平面图整体发白，房间轮廓看不清 | 地板（0.43）与墙（0.70）明度太接近 | 地板压到 0.35，加大明度差 |
| 10 | 顶视平面图讲台跑到下方，或整张图左右翻转 | 顶视时 `to_track_quat` 的滚转不确定 | 平面图直接指定 `euler=(0, 0, math.pi)` |
| 11 | 方案书一度超过 5 MB，微信发不出去 | 直接把 2 MB 级 PNG 转 base64 内嵌 | 先 `img.scale(1100, h)` + `save_render()` 转 JPEG，单张压到 40–130 KB |

### 5.2 三条值得单独说的

**(1) 中文界面是隐形的坑。** 节点名被本地化只是表象，真正危险的是 `next(..., None)` 拿到 `None` 后代码继续执行——材质球建出来了、颜色却全是默认值，而且不报错。后来所有节点查找都改成 `bl_idname`，插槽名保持英文（这部分没有被本地化）。

**(2) 洞口类构件不能建成实心块。** 窗、门、任何开孔都必须用「边框条围合」的方式建，一旦建成实心块，玻璃/门扇藏在里面，从外面看永远是一块板。这个坑在窗户上卡了两轮才定位到——因为第一反应总是怀疑玻璃材质或透明设置。

**(3) 剖切图的黑屏其实是灯光被误杀。** 为了让剖切图不出现悬空的灯罩，第一版把 `Lamp_*` 全部 `hide_render`。但 Area 灯是以 `LIGHT` 对象单独存在的，名字相近，一起隐藏后室内失去全部照明。正确做法是把「灯具实体」和「光源」当成两类对象分别管理。

## 8. 可拆解模块（附文件清单）

![模块可复用性](images/module-split.png)

### A. 可直接复用：`lab_lib.py`（259 行，零业务耦合）

**文件清单**：`lab/lab_lib.py`（单文件，无同级依赖）

**提供能力**：`clear_scene()` 场景复位、`box()` 纯数据图元（直接 `from_pydata`，不经过操作符）、`cyl()/join()/bevel()` 内置操作符封装（`--background` 下可正常运行，无需 UI）、`mat()` 建 PBR 材质、`add_grain()` 程序化木纹节点组、`make_materials()` 一套 11 组色板、`build_desk()/place_desk()` 座位单元与实例化。

**接入方式**：

```python
import sys; sys.path.insert(0, r"<你的路径>/lab")
import lab_lib as L
L.clear_scene()
M = L.make_materials()
```

**接入注意**：文件顶部的 `OUT` 是绝对路径，必须改成自己的输出目录；`LAYOUT_X/LAYOUT_Y` 是本项目结论值，复用时替换成自己的坐标表。

### B. 改常量即可复用：`build_classroom.py` 的建筑围护段（约 130 行）

**文件清单**：`lab/build_classroom.py` 第 81–208 行（地面/吊顶、四面墙、窗带与门洞、室外环境、讲台墙、教师桌、走线标线、机柜/空调、踢脚线、灯具阵列）+ 第 210–231 行的 `shoot()` / `hide()` 出图工具。

**提供能力**：任意矩形教室/会议室的围护结构生成（分段砌墙算法可处理任意窗洞/门洞数量）、灯带与 AREA 灯对位、玻璃半透材质（`surface_render_method='BLENDED'` + Alpha 0.18）、相机与可见性工具。

**接入注意**：需同步改 `ROOM_W/ROOM_D/WALL_H/WALL_T`、`WIN_C`（窗中心 Y 坐标数组）、`DOOR_C/DOOR_W`、`LAMPS`；讲台墙与机柜坐标是本案位置，建议整段删掉重写。

### C. 换内容即可复用：文档流水线 `build_doc.py` + 模板 + SVG（52 + 442 + 203 行）

**文件清单**：`lab/build_doc.py`、`lab/doc_template.html`、`lab/svg_dims.svg`、`lab/svg_zones.svg`、`lab/svg_cable.svg`

**提供能力**：任意「技术方案书 / 验收报告 / 设计说明」的单文件 HTML 产出。核心就是一张 token → 文件的映射表 + base64 内嵌 + 未替换自检。

**接入方式**：复制模板改版式 → 把图片位置写成 `@@IMG_XXX@@` → 在 `build_doc.py` 的映射表里加一行 → 跑脚本看 `unresolved` 是否为 `[]`。

### 不建议直接搬的部分

`build_all.py`（课桌三视图专用机位）、`LAYOUT_X/LAYOUT_Y` 的具体数值、讲台墙设备坐标、`web/*.jpg` 压缩产物——这些是本案的**结论**而不是**能力**，换项目必须重算。

## 9. 复现步骤

```bash
# 1) 课桌单体三视图 + 机房整体轴测/平面
blender -b -P lab/build_all.py

# 2) 完整教室 + 11 个视角渲染（EEVEE 96 采样 × 6 个教室视角，耗时取决于显卡）
blender -b -P lab/build_classroom.py

# 3) 组装方案书（纯 Python，不需要 Blender）
python lab/build_doc.py
#   → OUT: .../机房课桌设计方案.html
#   → bytes: 1337231
#   → unresolved: []
```

改方案的正确姿势：

1. 只改**房间尺寸** → 改 `lab_lib.py` 的 `ROOM_W/ROOM_D`，并同步 `build_classroom.py` 里的 `WALL_H/WALL_T` 与窗门坐标；
2. 改**座位数** → 增删 `LAYOUT_X` / `LAYOUT_Y` 元素，检查分段和是否闭合；
3. 改**桌型** → 改 `L/D/H/LEG/LEG_X/RAIL/SEAT_X`，几何与走线槽会联动；
4. 改**文案与章节** → 只动 `doc_template.html`，重跑第 3 步。
