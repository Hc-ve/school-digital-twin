## 2. 已识别的 5 个风险（按严重度排序）

### 🔴 2.1 中文字体缺字（**最大隐患，必须在答辩机器上实测**）

**事实**：项目字体走 `Font.CreateDynamicFontFromOSFont`，**运行时向操作系统借字体**
（`TwinUIFactory.cs:58`），候选链是 `Microsoft YaHei UI → Microsoft YaHei → 微软雅黑 →
SimHei → ... → Arial`，兜底是 `LegacyRuntime.ttf`。
而 `TwinUIFactory.cs:28` 的注释自己写明：**Unity 内置的 `LegacyRuntime.ttf` / `Arial.ttf`
不含 CJK 字形，中文会显示成方框或空白**。

**风险**：如果答辩机器**没装微软雅黑/黑体/宋体**（精简版 Windows、Ghost 系统、
某些实验室机器都可能没有），候选链全部落空 → 兜底字体 → **全界面中文变方框**。
这一条一旦发生，答辩直接废掉，比任何 bug 都致命。

**必做**：
1. 步骤 7 在答辩机器上**第一个看中文**。
2. **准备兜底**：U 盘里放一份 `msyh.ttc`（微软雅黑）或 `simhei.ttf`（黑体），
   万一答辩机器缺字体，拷进 `C:\Windows\Fonts` 双击安装，重启 exe 即可。
   （来源：从你当前这台机器的 `C:\Windows\Fonts\msyh.ttc` 拷一份，10 秒钟的事）
3. 演示视频是**保险**：视频里的中文是录进去的像素，不受机器字体影响。
   **万一现场字体崩了，直接放视频。**

### ⚠️ 2.2 天气系统在打包后可能失效（Shader 剥离）

**事实**：天气包的 4 个 Shader 里，程序化生成的材质需要放在 `Resources/` 才不被剥离
（杨续技术文档 §16 坑 1，已按此执行：`Assets/_Project/Scripts/Weather/Resources/`）。

**风险**：即便如此，**内置管线打包时未被任何场景材质直接引用的 Shader 仍可能被剥离**
（编辑器里正常、exe 里变粉/变黑）。这是"编辑器能跑 ≠ 交付物能跑"的典型。

**必做**：步骤 5 第 4 项**重点看**——切雨/雪后，地面是不是**粉色**（Shader 丢失）
或纯黑。若出现：
- 临时修法：把 4 个 Shader 加进 `Project Settings → Graphics → Always Included Shaders`
  （数组 size +4，逐个拖进去），重打一次包。
- 这个修法**要断点做**（改 ProjectSettings 属于工程设置，不是断点的 `Assets/_Project/Scripts/`
  边界，但只有他清楚 Shader 名字与顺序），我已在任务包里点明。

### ⚠️ 2.3 产品名是英文 `School`，exe 显示不专业

**现状**：`companyName: Hc-v` / `productName: School` → 产物是 `School.exe`。

**建议改**：Product Name = `校园数字孪生管理系统`（exe 变成中文名）。
**但注意**：Unity 的中文 exe 名在**某些旧版 Windows / 命令行**下会有编码问题。

> **裁决**：**Product Name 保持英文 `School` 不改**，改 `Company Name` 为 `Hc-v`→ 保持不变。
> **理由**：答辩机器环境未知，中文 exe 名的编码风险 > 显示专业度的收益；
> exe 叫什么评委不会看，**双击能不能跑才是全部**。
> **影响**：无。若想专业感，把快捷方式重命名为「校园数字孪生管理系统」即可，零风险。

### ⚠️ 2.4 工程 1.3 GB，首次打包慢，且 Build 目录会很大

**事实**：`du -sh Assets` = **1.3 GB**（含 SchoolScene 全套模型与贴图）。

**影响**：
- 首次 Build 预计 20~60 分钟，中途**别切场景、别改代码**（会触发重导）
- Build 产物可能 1~2 GB，**U 盘要留够空间**（建议 16 GB 以上，别用 8 GB 的塞满）
- **别把 Build 目录提交进 git**（`.gitignore` 已忽略常见目录名，若用了自定义目录名要手工加）

**建议**：Build 目录用 `E:\School-pro_Build\`，**别放 C 盘**（C 盘满了 Build 会失败且报错难懂）。

### ⚠️ 2.5 帧率可能低于编辑器（未做性能诊断）

**事实**：项目**从未做过性能诊断**（基线 §4.3 第 3 项列为待开展）。
已知负载项：天气系统（雨雪粒子 + 云穹顶 + 星空 + 地面积水/积雪多层透明）、
69 盏灯、机房 20 块屏的 RenderTexture、10Hz 数据推送。

**风险**：多层半透明叠加 = Overdraw，投影仪上可能掉帧（基线风险清单原话）。

**必做**：步骤 5 第 7 项时，**开着天气效果 + 站在机房（20 块屏同屏）** 看是否明显卡。
若卡：
- 第一刀砍**云穹顶 + 星空**（视觉贡献最小）
- 第二刀降低雨/雪粒子的 `maxParticles`
- ⚠️ **不要砍地面积水/积雪**——那是天气演示的主角，砍了等于没做
