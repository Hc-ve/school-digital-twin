## 项目简介

**校园数字孪生管理系统**是一个面向校园设备运维与可视化的 Unity 原型系统。以一栋教学楼为载体，将 363 个真实编号的设备点位映射到三维场景，实现从「看数据」到「控设备」的完整闭环，并内置昼夜天气仿真，可在完全离线的环境下演示。

**核心卖点：**

1. **五大管理模块全部打通**——数据监测 / 设备管理 / 电力管理 / 告警中心 / 数据统计，三级面板结构（总控 → 管理系统 → 五模块），判据 178/178 通过；
2. **时间天气双通道**——15 分钟压缩 24 小时昼夜循环，7 档天气随机转移；数据侧（温湿度等物理量）与视觉侧（光照/天空）经桥接层统一收口，避免状态分叉；
3. **工程化质量保障**——428 条机器可验证判据 + 100 条踩坑台账 + 10 份专题复盘，所有「现象 → 根因 → 修法 → 教训」均有据可查。

**为什么做这个项目：**

- 校园设备分散在不同系统里，运维人员缺少统一的空间化视图——本系统把设备点位叠加到三维场景，做到「点设备看数据、点告警定位设备」；
- 数字孪生演示常依赖网络与后端服务，现场一旦断网就白屏——本系统默认 Mock 数据源，离线状态功能完整；
- 昼夜与天气会显著影响室内光照和设备状态——本系统把时间天气做成独立仿真引擎，而非静态贴图，演示时能真实反映环境变化。

> 边界声明：本项目为**可运行原型**，非生产系统；截图展示的是原型能力，不代表任何真实校园的现场实时数据。

## 核心功能

**监测与管控**

- **数据监测**：363 点位实时状态、数值读数、趋势曲线
- **设备管理**：台账 / 搜索 / 类型 + 楼层双排筛选 / 详情卡 / 开关控制
- **电力管理**：TwinCircuit 20 节点三级回路，开关返回受影响设备清单与倒计时
- **告警中心**：四级告警、点告警定位设备、全链路时间线（含控制命令记录）
- **数据统计**：按 Category / Zone 聚合、Top5 能耗排名、数据源标识（实测 vs 估算）

**仿真与交互**

- **昼夜天气仿真**：15 分钟 = 24 小时，7 档天气（晴/多云/阴/雨/暴雨/雾/雪）按转移链演变
- **物理派生数据**：室温、湿度、CO₂、供回水温度随天气与时刻变化，非固定波形
- **三态漫游**：第一人称 / 第三人称 / 观景俯视，走近设备触发交互菜单
- **设备控制**：命令中心统一收口，开关操作带回读确认与拒绝理由
- **离线可用**：Mock 数据源自动兜底，无网络、无后端服务即可完整运行

## 技术亮点：双通道时间天气 + 质量工程

本工程最核心的技术决策是**时间天气双通道架构**——解决「数据说夜晚、画面还是白天」这类状态分叉问题。

### 双通道 vs 单一直接写入

| 维度 | 本方案（桥接层统一收口） | 分别直接写入两侧 |
|---|---|---|
| 状态一致性 | `TwinWeatherBridge.ApplyHour` 同时写数据侧 `TwinClimate` 与视觉侧 `EnvironmentState` | 两侧各自更新，时序不定，演示时天色与读数对不上 |
| 时刻来源 | `TwinClimate.HourOfDay` 单一真值（真实时钟与表盘覆盖都在此收口）| 两处各存一份 hour，手动调时后必然漂移 |
| 昼夜边界 | 桥接层 `ToTimeOfDay` 统一定义 06–17 Day / 17–19 Dusk / 其余 Night | 各处自己划边界，UI 说 18 点天黑、视觉说 19 点才黄昏 |
| 灯光联动 | 路灯、室内补光层均读 `EnvironmentState.timeOfDay` 与 `HourOfDay` 窗口 | 灯光各自判时，出现「白天路灯亮着」 |

> 实测踩坑：直接调 `TwinClimate.SetHourOverride` 只写数据侧，视觉侧停留在白天——这是项目早期反复出现「调时间没反应」的根因，后才确立桥接层为唯一入口。

### 质量工程：判据 + 踩坑台账

- **428 条机器可验证判据**：`grep` 命中数 / 文件存在性 / 数据口径一致性，全部可复现；
- **100 条踩坑台账（七类）**：A 技术坑 10 / B 17 / C 8 / D 排查方法论 26 / E 流程纪律 4 / F 资源归属 22 / G 数据真实性 13；
- **10 份专题复盘**：发黑问题总纲（六族判别法 + 7 案例库）、视频播放器泄漏、屋顶雪壳事故等。

**指标口径说明**：判据验证的是「工程结构与配置是否守住」，不是视觉验收。项目铁律 D5——**数值不得推翻视觉结论**；曾出现判据 15 条全绿但 play 验收 5 项不通过的情况，故最终以实际运行为准。

## 系统架构

```
场景层（SchoolSceneDay）
├── 测点锚点 TwinAnchor × 363  →  注册到 TwinRuntime 事件总线
├── 表现层 TwinDevicePresenter  →  设备发光 / 屏幕 / 状态染色
└── 交互层 TwinInteractPoint × 17  →  走近菜单 / 命令下发

数据层
├── MockDataSource（离线默认）  ←→  TwinClimate（物理量派生）
└── MqttDataSource（可选）       ←→  TwinCommandCenter（命令收口）
                    ↕
时间天气层
├── TwinClimate.HourOfDay（时刻单一真值）
├── EnvironmentState（视觉侧：天空/光照/环境色）
└── TwinWeatherBridge.ApplyHour（唯一写入口，双侧同步）

管理层（UGUI 三级面板）
└── 总控 → 校园管理系统 → 五大模块
```

## 快速开始

1. Clone 本仓库
2. Unity Hub → Open → 选择工程根目录
3. 首次打开等待资源导入完成（约数分钟）
4. 打开场景 `Assets/TirGames/SchoolScene/Scenes/SchoolSceneDay.unity`
5. 点击 Play——默认进入离线 Mock 模式，数据即刻可读

> 场景清单：`SchoolSceneDay`（主场景）、`SchoolSceneNight`、`SchoolSceneMenu`、`SchoolSceneAbandoned`。

**操作方式：**

| 操作 | 方式 |
|---|---|
| 漫游 | WASD 移动，鼠标转向；Q/E 升降，滚轮推进（观景模式） |
| 设备交互 | 走近设备 → 出现交互提示 → 点击菜单开关 / 查看数据 |
| 系统面板 | 总控面板 → 「校园管理系统」→ 五大模块 |
| 时间天气 | 工具行打开时间天气卡，拖动表盘设定时刻或切换天气档 |

> 调试入口：`TwinWeatherBridge.ApplyHour(23, true)` 是修改时刻的唯一可靠入口；直接改数据侧不会更新画面。

## 配置

本工程默认零配置运行。如需接入真实 MQTT 数据源，在 `MqttDataSource` 中配置 broker 地址与主题；断线时自动回退 Mock。

| 数据源 | 用途 | 默认状态 |
|---|---|---|
| `MockDataSource` | 离线数据生成（含物理派生） | ✅ 启用 |
| `MqttDataSource` | 真实设备接入（MQTT over WebSocket） | 可选，需配置 |

> 设计边界：切换数据源时场景侧代码零改动——这是项目早期确立的「换数据源不改场景」原则。

## 故障排查

| 现象 | 原因与处理 |
|---|---|
| Unity 报 `CS0246` / `CS0103` 找不到类型 | 检查缺失的 `using` 命名空间（如 `SchoolTwin.Command`）；编译错误未清零时无法进 Play |
| 打包后机房视频/幕布失效，Player.log 报「找不到着色器」 | `Shader.Find("字符串")` 被打包可达性分析剥离——将 Shader 加入 Always Included Shaders（F22） |
| 改了参数画面纹丝不动 | 先确认「改的那条路径今天是否执行」：有烘焙产物 + 运行时双路径的功能，默认怀疑烘焙路径优先（P43 白片坑）|
| 调时间后画面仍是白天 | 直接改了数据侧；必须走 `TwinWeatherBridge.ApplyHour(hour, true)` 同时更新视觉侧 |
| 白天/夜间灯光随视角忽明忽暗 | 光源启用逻辑挂在相机上；需改为跟随角色并加滞回（见路线图） |
| 雪幕走一段突然空了 | 发射盒跟随角色 + 落程延迟；改为世界空间覆盖或加大补播（见路线图） |
| git push 报 502 / CONNECT tunnel failed | 代理端口会漂移，先重测连通性再换端口；curl 探测在本地可能假阴性，以 git 自身报错为准 |
| ProjectSettings.asset 出现 Android 图标块 | Unity/MCP 连接自动回写的 PICO 残留，还原即可，不要提交 |

## 已知限制

- **编辑器内帧率偏低**：完整光照体系下约 7~8 fps（编辑器 + 桥接开销，仅供量级参考）；瓶颈在逐像素灯预算而非灯数本身，最终以打包实测为准
- **离线 EXE 比当前代码旧**：最新打包产物在 D13 修复后产出，此后又有多次提交（天气/设备/灯光），未逐次重打包
- **四项待返工**：视角相关灯光/光池稳定性、雪幕区域性空窗、室内粒子穿透、饮水机控制接入（见路线图）
- **判据非全绿**：428 条中 9 条为历史遗留未过（P13/P28/P43 老判据），与当前功能无关但尚未清理
- **无真实生产流量验证**：本项目为原型，数据来源为 Mock 或可选 MQTT 接入，未经真实校园规模检验
- **部分历史素材保留**：`*Old.png` 系列为素材包原始文件，未删除以避免断引用

## 开发约定

- **写入者不启动编辑器**：GUI 验收由主理人执行，执行方交付「已写 + 已编译 + 静态自检」
- **验收通过即提交**（E4）：同一轮内 commit；二进制素材与 `.meta` 必须入库
- **不提交半成品**：成员正在写入的文件不进暂存区
- **数值不得推翻视觉**（D5）：判据全绿不等于验收通过
- **改时刻只走桥接层**：`TwinWeatherBridge.ApplyHour`，禁止直写数据侧
- **新截图用唯一文件名**：禁止覆写 `Docs/QA/evidence/` 下已入库的历史证据
